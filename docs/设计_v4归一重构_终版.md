# v4 归一重构 · 终版设计（设计者出品 2026-10-20）

> 目标：数据全部经后端落盘整合后由前端消费投影，流式/重渲归一；UI 零变化；
> 子代理三红线；动画四红线。已定决策（协议封闭五操作、子代理独立 topic、
> 灰度开关）不再翻案。本文档只含方案与伪代码，不含实现代码。

## 0. 结论先行

| 核心问题 | 决策 |
|---|---|
| 渲染层路线 | **废弃 v4render.js 的「适配旧基元」路线，新建 v4view.js 独立渲染层**：按 row.kind 直接产出与旧 UI 逐 class 一致的 DOM；组头/占位/spinner/秒表全部由投影行纯函数派生，不读不写 `_HG.grp/_hgFlow` 等全局状态机 |
| 旧基元复用边界 | 只复用**无状态纯叶子**：renderMd/mdBubble/attChipsHtml/esc（ask-md.js）、diffHtml/statusBadge（tools.js）、hgToolCard 的**卡片内部构造抽成纯函数 hgToolCardInner**（tools.js 内拆出，不带走状态机部分）。renderUser/renderAsst/renderToolUse/grpEnsure/grpFinalize/phStart/endThinking/closeRun/_tlPlace 等一切带状态机者**不进 v4 管线** |
| turn 权威 | turn_header 行 + state(busy/curTurn/model/queue) 由后端 reducer 唯一产出；前端 v4view 按 rows 顺序把同 turnId 行归入同一 `.h-grp`，纯函数派生组头文案/秒表/折叠态 |
| 用户消息红线 | commandId 链路已通（前端生成→POST body cmd→session.py:929 user_echo 带 cmd→user_input.cmd 行→v4store reconcile）；补两处：POST 携 cmd 落到所有发送入口、watchdog 已有 2s。**绝不本地伪造用户行** |
| 子代理红线 | 主投影在 `_reduce_cli` 加 `parent_tool_use_id/isSidechain/isMeta` 过滤（当前缺失，P0）；子 pane 走 sub topic 独立 store+v4view；结论只由 state.final 渲染一次 |
| 冷启动 | 现有「transcript hydration 打底 + 账本水位后补放」保留，补 user_input 去重键（cmd/文本+ts 邻近）与 result 帧兜底收口 |

## 1. 架构总图

```
CLI 子进程
  │ stdin(jsonl)                ┌── transcript.py(CLI jsonl 落盘=历史权威)
  ▼                             │
session.py emit ──落账──▶ eventlog store (seq/epoch)
  │                              │
  └─ v4hub.v4_ingest_main ──▶ v4feed.V4Feed(main)   ←─ 懒建: _hydrate_main(transcript打底)
                                          │                + events_after(h) 补放
subagent_watch watcher ──▶ v4hub.v4_sub_ingest ─▶ V4Feed(sub:<agent>) ←─ hydrate_jsonl 三源
                                          │
routes.py /v4/stream (SSE) ◀─ frames_after/snapshot_wire
      │ ack(snapshot|resume) + frame(snapshot|deltas) + ka
      ▼
v4store.js  (前端唯一状态: 快照+overlay对账; 断档=forceSnapshot重订阅)
      │ {kind:'snapshot'|'deltas'}
      ▼
v4view.js  (新建; DOM=投影纯函数; rowId→DOM 增量; 无全局状态机)
      │ 产出与旧 UI 完全一致的结构:
      ▼
.h-grp > .h-grp-proc > .h-turn-head(工作中Ns/已工作X) + .h-turn-body
        > .h-drawer.think + .h-tl   ┃ 组根正文 .h-msg.asst / .h-msg.user / .h-mmeta
        (纯叶子: renderMd/diffHtml/statusBadge/attChipsHtml/hgToolCardInner)
```

设计不变量（铁律）：
1. DOM 是投影的纯函数：同一快照渲染任意次结果逐字节一致（验收用）。
2. 前端不产生会话事实；overlay 只喂 watchdog 不渲染。
3. 结构表达不了 → 服务端发 snapshot，前端无猜结构代码路径。
4. ingest 挂接只经 v4hub 两点（session.emit / watcher），禁止绕过。

## 3. v4view.js 关键状态机（伪代码）

### 3.1 数据结构
```
View = {
  flowEl, rowEls{rowId→el}, grpEls{turnId→grpRoot},
  timerInterval,     // 单只：每 500ms 重派生活动组头秒表
  conclEl,           // 子 pane 结论区（可选）
}
```
无 `_HG.grp` 类单活组概念：组由行的 turnId 标签派生，天然多组并存、无认回逻辑。

### 3.2 rebuild(snap)（snapshot 整窗）
```
clear(flowEl); rowEls={}; grpEls={}
for row in snap.rows: placeRow(row)          // 追加式，天然有序
paintState(snap.state)                        // spinner/输入框态/queue
```

### 3.3 placeRow(row) —— 按 kind 分发（唯一行渲染入口）
```
kind→结构（与旧 UI 逐 class 对齐）:
 turn_header: grpRoot=div.h-grp; proc=div.h-grp-proc;
              head=button.h-turn-head(chev+label+sub); body=div.h-turn-body
              (think 抽屉与 .h-tl 惰性：首个 reasoning/tool_call 行到达才建，
               display:none 起步=无空壳胶囊)
 user_input : 归入 turnId 组根（组根直挂，proc 外）div.h-msg.user
              (mdBubble(text)+attChipsHtml(files,images)+h-macts 由后端行字段)
 assistant_text: 归入组根 div.h-msg.asst + .h-mmeta(model)
 reasoning  : 组内 think 抽屉 body 追加思考段（首段置抽屉 display=''）
 tool_call  : 组内 .h-tl 追加 hgToolCardInner(tool,status,input,output,dur)
              空态占位由 status==='running' 派生，终态 upsert 换整卡内容
 subagent   : .h-tl 追加子代理行卡（status 徽章+summary+下钻按钮）
              绝不含正文（红线）
 vision/peer_notify/marker: 同构单行卡
```

### 3.4 applyDelta(d)
```
row.appended  → placeRow(row)（若 turnId 组不存在：懒建组=兜底，后端漏
                turn_started 也不白屏；turnId 空（marker）→ flow 直挂）
row.upserted  → el=rowEls[id]; 存在则替换整 el（含 tool 终态徽章/输出区
                一次成型——不做「建卡再回写」的双开销）；不存在=越窗 no-op
row.delta     → 定位行内 text 节点 append（流式文本平滑）
row.removed   → 摘 fromRowId 起的全部 el 并清 grpEls 对应
state.updated → paintState：busy→spinner 派生、queue→队列条、model→chip
```

### 3.5 组头派生（纯函数，每帧+500ms tick）
```
grpHeadPaint(hdr):                 # hdr=turn_header 行
 state==='running':
   label = '工作中 ' + fmt(now - (hdr.startedAt||hdr.at))   # live 秒表
   spinner 显示条件 = 该组是 rows 中最后一个 turn 组
                    AND snap.state.busy
                    AND 组内无 pending 的 assistant_text/tool（防占位残留：
                      正文已到即撤 spinner；tool running 时由工具卡自身动画表现）
 state in (success|cancelled|error):
   label = '已工作 ' + fmt(hdr.activeMs || endedAt-startedAt)
   err 时附 err 短文案；撤 spinner；think 抽屉折叠态保持
sub 位置（· N 思考 · M 工具 · K 识图）= 遍历组内行按 kind 计数，纯派生
```
占位气泡策略（红线：不残留）：v4 **不预建占位**——「正在执行动画」由
spinner（state.busy）与 tool_call running 卡承担；正文到达即 append，无
「先占位后让位」的让位窗口，构造性消灭残留。

### 3.6 子 pane 结论区（红线：结论正确、只渲染一次）
```
每次 snapshot/delta 后统一 derive：
  if snap.state.done && conclEl 且未渲染标记:
      conclEl = mdBubble(snap.state.final 或最后一条 assistant_text)
      撤「工作中」秒表/label
  结论去重：state.final 与最后一条 assistant_text 文本相同 → 结论区
      只渲染 final 一处（行流里不再重复画最后一条——reducer 已在
      SubagentHandback 归并为 assistant_text，view 端只画行流、结论区
      画 state.final；二者一致时结论区复用行流尾行元素，不复制）
```

## 5. 三条特殊链路设计

### 5.1 用户消息（红线：必须出现）
1. 前端所有发送入口：`cmd=V4Main.newCmd()` 进 POST body；queue_admit 用
   eid 同源（queue 泵发的 user_echo 也带同一 eid→cmd）。
2. store.markPending(cmd)（已有 2s watchdog + overlay TTL 20s）。
3. 后端 stdin 写成功→`_turn_start()`→`turn_started`→`user_echo(cmd)`，
   事件顺序保证组头先于或紧随用户行——组头「立刻出现」由 turn_started
   事件保证（stdin 写成功即发，session.py:902 注释已确认此序）。
4. reconcile 命中即撤 overlay；超窗→forceSnapshot 重订阅拿服务端权威，
   **绝不本地画**。ACK 判死 15s/静默 20s/断线 1s 退避重连已有。

### 5.2 子代理（三条红线）
- **不进主窗**：`_reduce_cli` 入口加
  `if o.get('parent_tool_use_id') or o.get('isSidechain') or o.get('isMeta'): return []`
  （对齐 subagent_projection.py:104 与 session.py:442 判据）。主投影的
  subagent 行只带 childTopic/summary/status。hydration 端 _hydrate_main
  已排除 sub_* 段（v4hub.py:147），两路对齐。
- **实时刷新**：watcher（lifecycle 启动、永不死）→ v4_sub_ingest → 子 feed
  delta → 子 pane SSE。子 feed 缺失时静默（未订阅不建）；首开 pane 时
  hydrate_jsonl 全量打底 + 订阅后 watcher 继续推增量——offset 由 watcher
  内存维护，hydrate 发生在订阅请求线程，竞态窗口 = hydrate 读取期间
  watcher 也在读同文件：watcher 推的行 hydrate 也读到 → 行重复。**补**：
  v4_sub_ingest 前对行做「文件内 uuid 去重」——feed_jsonl_line 增加可选
  `seen_uuids` set（jsonl 行有 uuid 字段则记，重复行 no-op）。无 uuid 的
  旧格式行以 (type, message.content 哈希, tid) 近似键去重。
- **结论正确**：state.final 由 result 行归约（已有）；view 层 §3.6 一次成
  型；后端重启后子 feed 重建（hydrate 全量）结论仍在；「已给结论但渲染异
  常」根治点 = upserted 整卡替换 + 结论区渲染标记位。

### 5.3 冷启动一致性（白屏/重复/丢尾）
现有：hydrate(transcript 全量权威) + `events_after(h)` 补放（a7 修复）。
校验结论：**方向正确，两处残留风险**：
1. **重复**：user_echo 在账本 seq>h 但 transcript 也已落盘（水位取值时刻
   与 CLI 落盘竞态）→ 同一用户消息画两次。补：v4hub 补放 user_echo 前
   查 hydration 已建行（cmd 相同，或 text 相同且 |ts 差|<5s）→ 跳过。
   turn_started 同理：`turn` 键已建 `_turn_rows` 即跳（reducer 已幂等）。
2. **丢尾**：epoch 变更（rewind）时旧 feed 丢弃重建，已有；无需 lines_seq。
   epoch 空串（子 feed）不带续传语义，重连恒 snapshot——可接受（子 pane
   全量小）。
