# 三角色设计真任务实测报告

- 日期：2026-09-20
- 背景：`43ca042`（harness v2.28-2.30）落地三角色设计——决策者（主对话）派发、
  执行者 executor（轻快模型，信息收集/排查/机械活）、编程者 coder（高级模型，
  攻坚实现）。角色定义由 `src/harness_roles.py` 生成到 `.claude/agents/`，
  会话内注册为可派发的 subagent 类型。
- 测试方式：决策者并行派发两个**真实任务**（非玩具用例），验收产出质量。

## 用例设计

| 用例 | 角色 | 模型 | 任务 | 验证点 |
|---|---|---|---|---|
| U1 信息收集 | executor | haiku | 取证三件事：保存日志内容、snip.py 提交史（8 条）、web/ 下 `/api/snip/` 引用清单 | 结论先行、只报事实不做决策、快 |
| U2 代码清理 | coder | opus | 清理 `src/snip.py` 遗留死变量 `_TMP_PNG`（底图改 BMP 后仅剩 geo json 拼接在用），要求独立定义路径+语法自测 | 可运行交付、改动摘要+决策理由+自测结果、不越界 |

## 测试结果

### U1 executor ✅

- 29s 完成，3 次工具调用，32.7k tokens——轻快模型成本符合定位。
- 产出质量：三节各一段、每节第一句即结论；纯事实无方案输出，符合角色约定。
- 附带价值发现：`%TEMP%\fc_snip_save.log` 不存在 → `adbaeb5` 的保存链路日志
  尚未被真实触发（保存修复待用户重启工具后实测）。

### U2 coder ✅

- 114s 完成，9 次工具调用，37.2k tokens。
- 交付物：`_TMP_GEO` 改独立定义（`fc_snip.bmp.geo.json`，沿"底图名.geo.json"
  伴生命名约定），删除 `_TMP_PNG`，补中文注释说明原因。
- 决策者复核（git diff + ast）：改动仅 3 行、零越界、语法通过、注释风格与
  项目一致。coder 汇报的"全项目无其他引用"经复核属实（server.py 只引用
  `_TMP_BMP`）。
- 边界遵守：未达主动提交阈值时未自行 commit，交由决策者处置，符合约定。

## 结论与观察

1. **链路可用**：`harness_roles.py` 生成的 executor/coder 在会话内注册生效，
   双角色并行派发、各自按角色约定交付，三角色分工闭环跑通。
2. **成本结构符合设计**：executor（haiku）快而省处理机械取证，coder（opus）
   处理代码攻坚，决策者负责验收把关——模型档次与任务难度对位。
3. **注意点**：会话中断会杀掉后台 agent 且无完成记录（本次首轮派发即被杀，
   重派后完成）；重要派发建议前台等待或及时验收落盘。
