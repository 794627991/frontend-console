## 一、我的方案为什么无效（自我复核）

外网在 §1.1 指出：

> `_cur_d[worker_name] = (r, time.time())` 每进入一个目录刷新。
> 893 个目录 / 60 秒 = 每分钟 893 次刷新。
> 时间戳**永远不会超过 0.07 秒**，更别说 180 秒。

**核实：完全成立。**

我的实测数据自己就证明了：

```
hikudev-head: 60 秒内处理 893 个目录
```

0.067 秒/目录。看门狗永远等不到 180 秒。

**我把「慢」误判成「卡」了。**
用户要解决的问题是「一个包扫太久拖垮整体」，不是「某行代码挂死」。
判据必须以**任务单元**计时，不是以「是否有进展」计时。

## 二、撤回「seed 拆细」提案（我曾向外网提出，现撤回）

### 2.1 我当时的错误判断

我模拟了 `_walk_files(root, subs=['.'])` 的 seed 构造，得到：

```
G10: seed 数=10  层级=L1
   configs docs kernel libs modules sbuilder test tools uboot zoos
```

据此认为 `sbuilder` 整体是一个 item，180 秒会丢掉全部 62 个包，
于是提出「拆细 seed 构造」方案。

### 2.2 核实后：artifact walk 的 seed 已经是包级

`nav_index.py` 里有**两条独立的 walk**：

**路径 1：主 walk（代码收录）**
```python
_walk_files(root, subs=sc["include"])      # include = ['.']
```
seed = L1 顶层目录。**但 `sbuilder` 在 `exclude_paths` 里，主 walk 根本不进入。**

**路径 2：artifact walk（产物源扫描）**
```python
_walk_files(root, subs=sc["artifact_roots"])   # = ['sbuilder/output/build']
```
`subs` 直接就是 `sbuilder/output/build`，作为 base 被 `_scandir` 后：
```python
l1_ds = 62 个包目录           # 62 >= N_WORKERS(8)
seeds.extend(os.path.join(base, d) for d in l1_ds)
```

**seeds 就是 62 个包目录，每个包一个独立 item。**

### 2.3 结论

| 路径 | seed 粒度 | 是否有问题 |
|---|---|---|
| 主 walk（`subs=['.']`） | L1 顶层目录 | 无——`sbuilder` 被 exclude，其余顶层目录实测 ≤13 秒 |
| **artifact walk（`subs=['sbuilder/output/build']`）** | **62 个包目录** | **无——`hikudev-head` 自然是独立 item** |

**现有的 seed 构造在需要精细化的路径上已经是正确的粒度。**
我提出的「拆细」是多余的，撤回。

### 2.4 主 walk 的其他顶层目录耗时（六平台实测，均远低于 180 秒）

| 平台 | kernel | modules | uboot | rootfs | tools |
|---|---|---|---|---|---|
| G10 | 9.4s | 0.6s | — | — | — |
| H8 | 12.9s | 1.4s | 0.5s | 5.5s | 0.6s |
| H11 | 12.0s | 0.4s | 8.3s | 3.6s | 0.5s |
| H9 | 10.1s | 1.3s | 4.2s | 2.4s | 3.5s |

| H13 | 9.1s | 0.8s | 4.2s | 2.0s | 0.5s |

**最大 12.9 秒，180 秒阈值有 14 倍余量。**

## 三、采纳外网的 item 级超时方案

### 3.1 实现

```python
_STALL_LIMIT = 180.0        # 单 item 超时（用户定调）
_WD_TICK = 5.0
_MAX_WORKERS = 16           # worker 上界（用户定调）

# 每个 worker 当前处理的 item 及起始时间（含世代号防竞态）
_sub_start = {}             # worker_name -> (sub_abs, t0, gen)
_gen = [0]                  # item 世代号自增
_dead_workers = {}          # worker_name -> gen（被判死的世代）
_live_workers = set()
_dl = threading.Lock()
_stop_wd = threading.Event()
```

**worker 取到 item 时**：
```python
sub = work_q.get_nowait()
with _alock:
    _gen[0] += 1
    my_gen = _gen[0]
_sub_start[me] = (sub, time.time(), my_gen)
```

**看门狗**：
```python
def _watchdog():
    while not _stop_wd.wait(_WD_TICK):
        if _abandoned[0]:
            return
        now = time.time()
        for name, (sub, t0, gen) in list(_sub_start.items()):
            if now - t0 < _STALL_LIMIT:
                continue
            with _dl:
                if name in _dead_workers:
                    continue
                _dead_workers[name] = gen        # ← 记录世代号
            rel = os.path.relpath(sub, root).replace(os.sep, "/")
            with _alock:
                stats.setdefault("timeout_items", []).append({
                    "rel": rel,
                    "elapsed": round(now - t0, 1),
                })
                stats["timeout_pruned"] = stats.get("timeout_pruned", 0) + 1
            _sub_start.pop(name, None)
            _cur_d.pop(name, None)
            with _alock:
                _active[0] -= 1
                _last = _active[0] == 0
                _n_live = len(_live_workers)
            say("  ⚠ 目录扫描超时 %ds，已跳过：%s" % (int(_STALL_LIMIT), rel))
            if _n_live < _MAX_WORKERS and not work_q.empty() and not _abandoned[0]:
                _spawn_worker()
            if _last:
                _send_done()
```

### 3.2 worker 退出的世代号校验（外网 §6.1）

```python
finally:
    me = _th.current_thread().name
    with _alock:
        my_gen = _sub_start.get(me, (None, None, -1))[2]
        _sub_start.pop(me, None)
    with _dl:
        dead_gen = _dead_workers.get(me)
    try:
        _cur_d.pop(me, None)
    except Exception:
        pass
    with _alock:
        _live_workers.discard(me)
        killed = (dead_gen is not None and dead_gen == my_gen)
        if not killed:
            _active[0] -= 1
        _last = _active[0] == 0
    if _last:
        _send_done()
```

**外网指出的窗口**（看门狗判定与 worker 换 item 之间）由世代号解决：
- worker 换 item 时 `my_gen` 变了
- 看门狗记录的 `dead_gen` 是旧值
- `dead_gen != my_gen` → 不算死亡，worker 自己减 `_active`

### 3.3 worker 正常完成 item 时要清理 `_sub_start`

```python
for r, ds, fs in os.walk(sub, onerror=_on_err):
    _cur_d[me] = r          # 保持原结构（外网 §五）
    ...
# item 扫完
with _alock:
    _sub_start.pop(me, None)
```

**关键**：不清理会导致看门狗误判「这个 worker 还在处理旧 item」。

## 四、其余采纳项

### 4.1 `_loop_prune` 阈值不变（外网 §三）

**同意不改。** 我没有六平台在 >2 阈值下的误剪实测数据。

外网的理由也成立：
- `>2` 意味着「段名重复 3 次即剪」，`arch/arm/plat-xxx/arch/arm/...` 这类合法路径可能命中
- 改 >2 只省 1 层，无法解决 26 分钟问题
- 真正解决靠 item 级超时

**保留 >3 不动。**

### 4.2 `_is_sysfs_like` 改为默认关 + 告警（外网 §四）

**同意。**

外网指出的两个问题成立：
1. 首段是 `dev` 的工程会被误剪（很多工程用 `dev/` 存开发代码）
2. `test/sys` 在任何工程里都可能是合法的测试代码目录

**改为**：
```python
# 默认不剪，仅记录疑似 sysfs 目录
def _looks_like_sysfs(rel_l):
    segs = rel_l.split("/")
    # 只认「前一段是 test/tests 且当前段是 sys」这一条
    for i, s in enumerate(segs):
        if s == "sys" and i > 0 and segs[i-1] in ("test", "tests"):
            return True
    return False
```

在 `_walk_files` 里：
```python
if _looks_like_sysfs(rel_l) and stats.get("report_sysfs"):
    with _alock:
        stats.setdefault("suspect_sysfs", []).append(rel_l)
    # 继续扫描，不剪枝
```

建库汇总里显示：
```
ℹ 发现 2 个疑似 sysfs 导出目录（已按普通目录扫描）：
  sbuilder/output/build/hikudev-head/test/sys
  rootfs/test/sys
若确认无需索引，可加入排除列表。
[加入排除列表]
```

**是否开启这个默认关的开关**：建议加一个配置项 `report_sysfs_dirs`（默认 `True`，只上报不剪枝）。

### 4.3 `_cur_d` 结构不变（外网 §五）

**同意。** item 级超时只需要 `_sub_start`，`_cur_d` 保持 `thread_name -> path`。

停滞告警段（现有 120s 告警）不受影响。

## 五、推荐器的超时粒度（外网 §七）

外网指出推荐器与建库的任务单元不同：
- 建库：`work_q` 里是种子子树
- 推荐器：需要对**顶层每个目录**做完整统计

**外网的分析正确。** 但结合 §二 的发现，需要补充：

### 5.1 推荐器的实际扫描方式

推荐器要统计每个顶层目录的 `src`/`o`/`cmd`/`code`。若复用 `_walk_files`：

```python
for top in 顶层目录:
    for abs_p, rel in _walk_files(root, subs=[top]):
        统计...
```

**每个顶层目录是一次独立调用**，seed 构造以 `<root>/<top>` 为 base：
- `kernel` 有 2 个子目录 → 不足 8 → 拆到 L2 → seed = `kernel/kernel_sdk`, `kernel/plat_private`
- `sbuilder` 有 15 个子目录 → >= 8 → seed = 15 个 L1 子目录
- `sbuilder/output` 有 5 个子目录 → 不足 8 → 拆到 L3 → seed = `sbuilder/output/{build,feeds,host,images,target}`

**`sbuilder/output/build` 作为一个 item**（62 个包）→ 180 秒超时会丢整个 build。

### 5.2 解决方案：推荐器单独设置 subs

**推荐器不应按顶层目录调用 `_walk_files`，而应按「需要统计的单元」调用。**

```python
def recommend_scope(root):
    tops = listdir(root)          # 12 个顶层
    for top in tops:
        # 若该顶层目录本身很大，先 try 一次 L1 seed
        # 若 L1 子目录 < 8，拆到 L2
        # 若 L2 子目录 < 8，拆到 L3
        # → 与 _walk_files 的 seed 构造一致
        stats = count_three_tuple(root, top)
```

**实际做法**：直接复用 `_walk_files`，它会自动拆到合适粒度。
唯一的问题是 `sbuilder/output` 只有 5 个子目录（< 8），不拆到 L3。

**建议：推荐器给一个更大的超时**（300 秒/顶层目录），并在超时时降级为「按子目录分别统计」：

```python
def _count_with_timeout(root, top, timeout=300):
    try:
        return _count_raw(root, top, deadline=time.time()+timeout)
    except TimeoutError:
        # 降级：按子目录分别统计
        subs = listdir(os.path.join(root, top))
        out = {}
        for s in subs:
            out[s] = _count_with_timeout(os.path.join(root, top), s,
                                          timeout=120)
        return merge(out)
```

**但这会让实现复杂。**

### 5.3 内网建议：推荐器用独立的一次性扫描

**推荐器不需要复用 `_walk_files` 的并发/环防护/取消机制。**

它只需要「**一个目录的三元组计数**」，可以用更简单的方式：

```python
def _count_dir(path, deadline):
    """返回 (src, code, o, cmd, timed_out)。
    deadline 到期立刻返回当前计数。"""
    src = code = o = cmd = 0
    stack = [path]
    while stack:
        if time.time() > deadline:
            return src, code, o, cmd, True
        d = stack.pop()
        try:
            with os.scandir(d) as it:
                ents = list(it)
        except OSError:
            continue
        for e in ents:
            try:
                if e.is_dir(follow_symlinks=False):
                    nm = e.name
                    if nm.startswith('.') or nm.lower() in _SKIP_AND_TMP:
                        continue
                    # 环防护
                    stack.append(e.path)
                else:
                    ...计数...
            except OSError:
                continue
    return src, code, o, cmd, False
```

**关键区别**：
- 每个**顶层目录**一次 `_count_dir` 调用（12 次）
- 每次调用设置 deadline（如 120 秒）
- 到期返回已有计数 + `timed_out=True`
- **推荐结果仍可用**（部分数据 + 标注「`sbuilder` 统计超时，数据不完整」）

### 5.4 推荐器的超时阈值建议

| 层级 | 阈值 | 理由 |
|---|---|---|
| 单顶层目录 | **300 秒** | 实测最大 27.9 秒（E13 sbuilder），10 倍余量 |

**推荐器超时的后果**：该目录的三元组数据不完整 → L2/L3 判定可能不准 →
UI 上标注「⚠ 该目录统计超时，推荐可能不准，建议手动选择」。

### 5.5 为何推荐器可以用比建库更长的超时

- 建库：用户等着结果，180 秒可接受
- 推荐：用户本来就预期「要扫一会儿」（有进度条），300 秒可接受
- 且推荐器超时的后果轻（只是推荐不准，用户可改）
