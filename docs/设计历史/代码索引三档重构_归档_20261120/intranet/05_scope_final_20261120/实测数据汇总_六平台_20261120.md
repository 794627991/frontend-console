## 七、G10 `sbuilder/output/build` 的 `.cmd` 源归属

解析关键包的 `.cmd` 首行（Kbuild 格式 `savedcmd_x := gcc ... -c -o x.o src.c`）：

| 包 | `.cmd` 总数 | 源指向分布 |
|---|---|---|
| linux | 3,246 | 包内相对 2,300；解析失败 945；绝对路径 1 |
| optee-head | 911 | 包内相对 860；绝对路径 49；失败 2 |
| uboot | 475 | 包内相对 358；失败 117 |
| busybox-1.36.1 | 407 | 包内相对 348；失败 59 |
| hal_bsp-head | 1 | 解析失败 1 |
| boot-atf-head | 0 | — |

**包内相对路径样例**：
```
arch/arm64/hikdrvlib/hik_early_fdt_parse.c
arch/arm64/hikdrvlib/hik_gpio_fast_operation.c
core/drivers/../../bsp/mmz/drivers/src/smmz_common/drv_mmz_init.c
```

**绝对路径样例**：
```
/data1/gaoyi13/work/linux/g10/g10_trunk/kernel/kernel_sdk/lib/vdso/gettimeofday.c
/data1/gaoyi13/work/linux/g10/g10_trunk/sbuilder/board/ecbb_d2/external-recipes/../tools/musl/musl-1.2.3/src/malloc/...
```

**结论**：
1. `sbuilder/output/build/linux` 的 3,246 个 `.cmd` 与 `kernel/` 目录的 3,246 个数量相同，
   是同一批构建的 out-of-tree 副本 —— 印证现有代码注释「2285 个 .o.cmd 靠
   source_roots 解析回 kernel/kernel_sdk」
2. `artifact_roots` 设计**有效，必须保留**
3. 绝对路径指向 Linux 构建机（`/data1/...`），在 Windows 侧无法解析 →
   这是现有代码 `_parse_cmd_file` 的 `source_roots` 基准映射要处理的情况

## 九、关键比值一致性分析

### 9.1 内核类 cmd_ratio 高度稳定

| 平台 | 目录名 | cmd_ratio |
|---|---|---|
| G10 | kernel | 9.96% |
| H9 | kernel | 10.32% |
| E13 | **linux** | 7.85% |

**区间 7.85%~10.32%**，3% 阈值有 2.6 倍余量。目录名不同（`linux`/`kernel`）不影响判据。

### 9.2 libs 类特征极稳定

| 平台 | 源文件 | `.o` | `.cmd` |
|---|---|---|---|
| G10 | 206 | 96 | **1** |
| H9 | 257 | 97 | **1** |

| H13 | 218 | 82 | **1** |

**四个平台全部只有 1 个 `.cmd`** —— 这是 `hal_bsp` 等预编译库的典型形态。

### 9.3 rootfs 数据与推荐值不一致（已知）

| 平台 | 源文件 | `.o` | `.cmd` | cmd_ratio |
|---|---|---|---|---|
| H9 | 992 | 517 | 435 | 43.85% |
| H13 | 824 | 412 | 364 | 44.17% |

数据显示 `rootfs` 是正常编译的源码树（43~44%），但按用户定调**推荐 off**。
这是「经验默认值」而非「数据推导值」，用户可手动改。
