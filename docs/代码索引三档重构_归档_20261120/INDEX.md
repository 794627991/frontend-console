## 六、设计要点速查（最终态）

### 6.1 三档

| 档 | 语义 |
|---|---|
| 白名单 | 全树找 `.cmd/.o` 推编译单元；头文件走 `-I` + BFS `#include` |
| 手动配置 | 三态树（`whitelist`/`full`/`off`）+ 父子继承 + 推荐器预填 |
| 全量 | 整树全收，只跳隐藏/工具缓存/生成物 |

### 6.2 数据模型

```jsonc
{
  "version": 2,
  "mode": "whitelist | manual | full",
  "dirs": {"kernel": "whitelist", "kernel/tools": "full"},
  "artifact_roots": ["sbuilder/output/build"],
  "exclude_names": []
}
```

落盘位置：**只写工程根 `.fcpk-scope.json`**（方案 A），删除 `scope_store_path` 整套。

### 6.3 推荐器

L0 形态 → L1 名称 → L2 数量 → L3 比值，命中即停。
**完整递归统计**（六平台 18~48 秒），UI 展开到一级子目录，判定用顶层完整统计值。

### 6.4 阻塞防护（B0，与三档重构正交）

**item 级 180 秒硬超时**（不是目录级——内网原方案无效，因为该场景每分钟推进 893 个目录）。
超时放弃整棵子树，补 worker，上界 16。

### 6.5 排序层

`nm_lock` 修正为 `len(out) == 1 and out[0]["rel"] == nm_cand`。
4 个适配点（2 处 `in_build` 计算 + 2 处排序）。

## 十、过程记录：三轮自我更正

这个项目里双方各认过错误，记录在此供后续参考：

| 方 | 错误 | 谁指出 |
|---|---|---|
| 外网 | `len(out) <= 1` 在 `out > 1` 时仍会锁定 nm 源候选 | 内网（03/06 包） |
| 内网 | 目录级超时判据（每进一层刷新），在 hikudev 场景永不触发 | 外网（评审文档） |
| 内网 | 「拆细 seed 构造」提案（artifact walk 的 subs 已是包级） | 用户 |
| 内网 | 终版方案三处错：扫描粒度 / 环防护 >6 / 点目录一律剪枝 | 外网（N1/N2/N3） |
| 外网 | 漏读 `终版设计方案_20261120.md`（当时确实未收到） | 内网（W5） |

**有价值的协作模式**：一方提出方案，另一方用**实测数据 + 代码核实**反驳，
而不是各说各话。
