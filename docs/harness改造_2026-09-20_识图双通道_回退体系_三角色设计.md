## 1. 识图双通道体系（v2.28.x）

### 1.1 架构与关键认知

```
主通道  mcp__4_5v_mcp__analyze_image   ← BigModel 网关服务端注入+执行（黑盒）
兜底    mcp__vision__analyze_image     ← 本地 harness_vision_mcp.py（server 名 vision）
```

**必须记住的实测结论**（都踩过坑）：

1. **同名遮蔽**：本地工具若与网关注入工具同名（4_5v_mcp），网关赢——本地版
   永远不被调用（实测 log 零记录、零 tool_use）。所以本地版必须独立名
   `vision`。这是双通道设计的根基。
2. **网关变体只收远程 URL**：主通道传本地路径直接 1210。引导词教的是
   "消息自带 CDN 链接直接用"。
3. **`[1M]` 后缀 API 不认**：claude CLI settings 里的窗口选择器
   （如 glm-5.3-flash[1M]）发给 /v1/messages 直接 400。MCP 侧已做
   裸名优先 + 后缀变体降级（`_model_variants`）。
4. **flash 偶发空回复的真凶**：max_tokens=2048 被 thinking 全额吃掉
   （stop=max_tokens、块=[thinking]、正文为零）。**已改 8192**，同图
   复测 14s 一发即中。空回复仍有同模型补发一次的韧性重试（v2.28.7）。
5. **报错去噪**：`_model_name_err()` 判定"模型名错误"类噪音（1211 等），
   最终报错优先非模型名错误，防 [1M] 变体的 1211 遮真因。
6. **识图会话已退役**（ensure_vision_session 空操作）：引导词明令禁止
   SendMessage 转交（会话不存在=黑洞，模型曾"摆烂"直接转交，实测教训）。

### 1.2 配置（~/.serialconsole_pro/config.json 的 harness_vision 节）

```json
{"enabled": true, "model": "", 
 "model_map": {"open.bigmodel.cn": "glm-5.3-flash", "lanz.hikvision.com": "Lanz-Medium-V"},
 "mcp_prompt": "", "mm_extra": ["glm-5.3-flash", "Lanz-Medium-V"]}
```

- `model_map`：端点关键字→模型（**MCP 每次调用读盘，改完即生效**）。
- 模型解析优先级：env → model_map 最长命中 → model → 默认 glm-5.3-flash。
- `mcp_prompt`：识图 system（不读旧会话时代的 prompt 键——内含 SendMessage
  指令，对 MCP 是毒药）。
- 设置面板「👁 识图配置」编辑以上字段；开关 enabled 同时门控 MCP 注入
  （--mcp-config 与 --allowedTools 同步，v2.28.3）。

### 1.3 诊断日志

`~/.serialconsole_pro/vision_mcp.log`：每次本地兜底调用记 imageSource 摘要
（可判截断）/端点/模型/结果/耗时，512K 自动截半。**网关主通道不经过本地，
无日志**（这是已知盲区，见待办）。

### 1.4 显示（前端）

- 客户端执行的识图调用（两个工具名都识别）：📤 已转交分割线+秒表 →
  tool_result 到达定格（成功"📥 已回传·用时Ns" / 失败"⚠ 识图失败"）+
  📥 识图 回传气泡。按 tool_use_id 映射（并行多图各对各线，v2.28.3）。
- 网关服务端执行：织在文本流里（"🌐 Z.ai Built-in Tool"格式），无分割线
  ——**两执行者显示形态不同**，B 方案固有特性。
- 回放：`vision_relay` 行（含 ISO 时间戳自动算 dur）+ peer 结果行。
- 回合终结（result/interrupted/exit）`_hgVisionSweep` 收尾未回传的线。

### 1.5 MCP 端点与韧性（src/harness_vision_mcp.py）

- 端点解析：env HARNESS_VISION_BASE_URL/KEY → ~/.claude/settings.json 的
  ANTHROPIC_BASE_URL/AUTH_TOKEN（与主会话同源）→ 智谱直连兜底。
- 端点回落时模型跟着端点重新解析（lanz 端点不会拿 glm 模型去打）。
- 输入三态：本地路径（魔数校验，BMP 明确拒）/ http(s)（UA+15MB 上限+
  Content-Type 校验）/ data: URL（image/* 校验）。

## 2. 手动压缩与回退体系（v2.28.4-16）

### 2.1 /compact

- CLI 2.1.267 headless 下 stream-json 用户消息里的斜杠命令**真实执行**。
  前端 /compact 走正常发送管线，压缩分割线/耗时照常显示，支持保留要点
  （`/compact 保留XX`）。
- **超窗守卫放行了 /compact**（v2.28.10）——之前守卫一刀切把压缩命令也
  拦了（用户实锤"压不了"）。

### 2.2 砖死态（重要概念）

单轮巨量注入（实测：MCP 会话里 Read 一张 304KB PNG → 上下文 340K→1024K）
后，/compact 自身的压缩请求也超窗 → 会话砖死。**唯一解是回退**。
MCP 模式引导词已禁止 Read 图片取链接（防此炸弹），inline 多模态会话不受限
（Read 是它的正路，两套引导词互不干扰）。

### 2.3 /rewind（三模式，后端 /api/harness/rewind）

| 模式 | 参数 | 语义 |
|---|---|---|
| 回合计数 | turns: N | 丢最后 N 个完整回合 |
| 时间戳锚点 | ts: ISO | 截到 ts 所在回合的 result（备用） |
| 文本锚点 | anchor: 正文前缀 | **消息级回滚主路径**：从尾部找匹配 assistant 行，截到其后第一个 result |

共同机制：全量备份（`<sid>.jsonl.bak-时间戳`，历史永不丢）→ 原子截断 →
杀进程 → 下次发消息 --resume 续上截断后的转写。

### 2.4 消息级回滚按钮（前端，v2.28.15/16 终版语义）

- **每个"定下来的 AI 回合"的最后一条消息**有 ⏪ 回滚到这里按钮：
  - 授予：实时路径 result 事件结算；回放路径按 user 行边界标记。
  - 未完成的回合没有；回合中间的分段消息没有。
- 实现为 `can-rewind` 类 + `dataset.rwa`（正文前缀锚点）+ flow 级事件委托
  ——三样全部随 innerHTML 快照序列化/全局唯一，**切会话快照往返不坏**
  （曾因单例 DOM 引用方案出过"旧气泡残留双条"，已结构性消灭）。
- 点击 → POST {sid, anchor} → 后端截断 → `_hgReloadFlow()` 重拉转写重建界面。
- 复制按钮砍掉了（用户定调：太丑）。

## 3. A→B→A 双气泡修复（v2.28.13）

现象：A 发消息 → 快速切 B → 切回 A，同文同图消息画两条（AI 实际只收到一次，
纯显示层）。根因链：快照带乐观气泡回来 + 错过的 user_echo 重放 + echoFast
被切会话清空。修复双保险：echoFast 随快照存取 + `_hgEchoDup`（与最后一条
用户气泡同文同附件判定跳过，dataset 属性跨快照可比）。

## 4. 三角色设计（v2.29.x，src/harness_roles.py）

### 4.1 架构

| 角色 | 载体 | 模型 | 职责 |
|---|---|---|---|
| 决策者 | 主会话本身 | 高级模型 | 承接/拆解/派发/审核（亲自 Read coder 的改动）/汇总；**不下场干活** |
| 执行者 | agent `executor` | 轻快模型（默认 glm-5.3-flash） | 信息收集/查日志/排查/跑命令/debug/杂活 |
| 编程者 | agent `coder` | 高级模型（默认 glm-5.3） | 编码攻坚，改完自测再交 |

- **定义内置于 harness**（harness_roles.py），会话启动时
  `install_roles_agents()` 自动安装到 `~/.claude/agents/`（幂等：内容有变才
  写；配置改模型自动重生成）。别人装工具即得，零手工。
- 用 claude **原生 Task 子代理**（同步返回，不走跨会话 SendMessage）。
- **agent 文件 model 字段必须写显式模型 ID**（别名 opus/haiku 实测被无视，
  子代理会跑主链模型）。

### 4.2 开关（默认关！用户定调）

- 侧栏 `👥 三角色` 按钮：点击即切（POST /api/harness/roles）。
- **立刻生效机制**：角色词在引导词指纹（`_bridge_fp`）里——开关变化 →
  指纹变化 → 下条消息发送前的热更自动 kill+resume 换词重启（含/不含
  结构禁权）。已有会话无需重建，双向验证过。
- /roles 命令：显示三角色说明 + 当前方案解析出的实际模型。

### 4.3 模型三级解析（换 API 方案自适应）

```
① harness_roles.model_map 端点映射（显式指定，最高优先）
② 当前方案模型表自动识别（settings 模型映射；轻快词 flash/turbo/light/
   mini/air… → 执行者；其余默认优先 → 编程者；[1M] 后缀自动剥）
③ executor_model/coder_model 兜底
```
验证矩阵：智谱 ✓ / lanz（Lanz-Flash+Lanz-Auto）✓ / 单模型共用 ✓ /
映射优先 ✓。"不套娃"判定同源：主会话模型 == 执行者模型或带轻快词 → 不注入
决策者词。

### 4.4 结构禁权（行为管不住，只能结构封死）

决策者会话 `--disallowedTools Bash,Edit,Write,WebFetch,WebSearch,Glob,Grep`
（实测演进：禁 Bash → 它用 Glob 数数；禁 Glob → 用 Grep 数；全禁后老实派发
`Agent(executor)` ✓）。只留 Read（审核）+ Task + ask_user + 识图。

### 4.5 引导词要点（roles_bridge_text）

纯知识问答直接答不派发；查文件/数数也算活必须派 executor；coder 产出必须
亲自 Read 审核；审核可再派 executor 取证；子代理结论消化后再答。

  回合终结收尾（防中断后假"运行中"）。
