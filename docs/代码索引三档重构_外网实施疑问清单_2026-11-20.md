## Q5. a562 的 inc 池兜底，在按目录分组后如何执行

内网实测报告 §三 明确：a562 的两处改动**缺一不可**

| 改动 | 位置 | 实测效果 |
|---|---|---|
| `_lookup_prox()` | `_resolve_includes()` 内 | 单独存在时 `adc.c` 只触达 **2** 个头文件 |
| `-I` 为空的 inc 池兜底 | `build()` 的 `if not _inc_dirs:` 分支 | 加上后触达 **45** 个 |

v3 §八 说「保留并下沉 1/2/3 到每个 `whitelist` 目录内独立执行」。

**问题**：inc 池兜底的入口条件是「`-I` 提取为空」——这是**全工程级**判据，
不是目录级。若按目录分组后每个 `whitelist` 目录独立跑，判据怎么落？

**请给出内网期望的执行顺序**：

```
方案 A（我推测）：
  1. 全树 walk（whitelist + full 目录都走，off 剪）
  2. 全工程一次性扫 .cmd → 若 -I 为空，建工程级 inc 池
  3. 对每个 whitelist 目录：单元 → 同目录头 → _resolve_includes(工程级 -I + inc 池)
  4. 对每个 full 目录：全收

方案 B：
  每个 whitelist 目录独立建 -I 与 inc 池（同一工程内多次重复，慢但隔离）
```

v3 写的是「下沉」，但实测数据说明 inc 池是**工程级**的，下沉会破坏它。
**请确认用方案 A 还是 B，或者给出第三种。**

## Q8. `nm_lock` 方案乙的精确定义

内网实测报告 §2.3 对外网的方案乙做了补充：

> 建议 `len(out) == 1` 而非 `<= 1`，并加 `out[0]["rel"] == nm_cand` 校验

我原稿写的是：

```python
if nm_cand and len(out) <= 1:
    for c in out:
        if c["rel"] == nm_cand:
            c["nm_lock"] = True
```

内网建议改为：

```python
if nm_cand and len(out) == 1 and out[0]["rel"] == nm_cand:
    out[0]["nm_lock"] = True
```

**请确认这两种的差异在什么场景显现**：

- 我的版本：`out` 只有 1 个候选，且它是 nm 源 → 锁定
- 内网的版本：同上，**但 `out` 为空时都不锁定**（我的版本 `len(out)<=1` 在
  `out` 为空时循环不执行，效果相同）
- 差异只在 `len(out)==1` 但 `out[0]` 不是 nm 源时：
  - 我的版本：循环不匹配 → 不锁定
  - 内网版本：显式条件不满足 → 不锁定
  - **两者等价**

**所以我理解两个版本行为一致**，内网补充的是「显式表达意图」而非行为差异。
请确认我的理解，或者指出我漏掉的场景。
