# 提交版本号规则

> 2026-11-02 立于 a199（v3 修订）。本仓库多 AI 会话并行开发，版本号是
> 跨会话共享的唯一提交账本。当前水位：**a199**（以文末命令实时查询为准）。

## 一、格式（唯一合法，两种）

```
v4.0.0-aNNN 一句话中文描述（做了什么+为什么，用户拍板/实锤注明）
v4.0.0-aNNNx 一句话描述（某版本审核修复）
```

- `v4.0.0`：内部基线标识（v4 投影管线），长期不变，不参与递增
- `aNNN`：构建序号，**单调递增、永不重置、永不复用**；三位起步，超 999 自然进四位
- **字母后缀**（aNNN + 单个小写字母，如 a199a）：专用于**某版本的审核修复**——
  对 a199 的对抗审/回归修复用 a199a，再修 a199b；主号不动，与被修版本
  的关联一目了然。字母按 a/b/c… 递增；大写 `R/R2`（历史旧式）废止
- 工具的**发布版本**（2.4.0 等）是另一层，与 aNNN 无关，不混进提交头

## 二、取号方法（提交前必做）

**必须扫全历史取最大号**（只看最近几条会撞车，见文末事故记档）：

```bash
git log --all --format=%s | grep -oE '^v4\.0\.0-a[0-9]+' | grep -oE '[0-9]+' | sort -n | tail -1
```

+1 即下一个号。字母号只挂到被修版本的主号上。

## 三、多会话并行

- 提交前各自查号，查完尽快提交；撞号不改历史，message 注明后跳号续
- 禁止为对齐序列 rebase/reset（并行会话基线会被毁）

## 四、禁止

- ❌ 无号提交（v4.0.0 序列内）
- ❌ 其他格式（`v4.1.3` 单发式、日期式、大写 R 后缀）
- ❌ 跳过查询凭记忆取号
