# 提交版本号规则

> 2026-11-02 立（v4.0.0-a156）。本仓库多 AI 会话并行开发，版本号是跨会话共享的唯一提交账本——不守规则的直接后果见文末「历史遗留盘点」：三套格式并存 + 号段回退撞车，检索和追溯全部失灵。

## 一、格式（唯一合法）

```
v4.0.0-aNNN 一句话中文描述（做了什么+为什么，用户拍板/实锤注明）
```

- `v4.0.0`：内部基线标识（v4 投影管线），**长期不变**，不参与递增
- `aNNN`：全局单调递增的构建序号，三位十进制，**永不重置、永不复用、跨版本连续**（升级到 v4.1/v5 也不清零）
- 工具的**发布版本**（2.4.0 等，发布页/打包用）是另一层，与 aNNN 无关，不要混进提交头

## 二、取号方法（提交前必做）

**必须扫全历史取最大号**，只看最近几条会撞车（a142 撞段事故正是只看了近 5 条）：

```bash
git log --all --format=%s | grep -oE '^v4\.0\.0-a[0-9]+' | grep -oE '[0-9]+$' | sort -n | tail -1
```

输出 +1 即下一个号。当前水位见本文档开头标注，但**以命令实时查询为准**（文档可能滞后）。

## 三、多会话并行

- 各会话提交前各自查一次号，查完尽快提交，缩短撞号窗口
- 万一撞号（两个会话用了同一个 aNNN）：**不改写历史**，后到者在 commit message 正文注明「与 aNNN 撞号，跳号续」并直接用下一个可用号
- 禁止为对齐序列做 rebase/reset——并行会话的基线会被毁

## 四、禁止

- ❌ 无号提交（历史 1191 条无号是旧态，自本规则生效起不再接受）
- ❌ 其他格式（`v4.1.3` 单发式、日期式等）
- ❌ `R`/`R2` 修订后缀（历史 a155R/a155R2 的做法废止——修订也占一个新号）
- ❌ 跳过查询凭记忆取号

## 五、历史遗留盘点（2026-11-02，只记档不改写）

全历史号段占用：0–70、73–79、81、83–147、151–155（71/72/80/82/148–150 为历史空洞，不回填）。

三段乱象，均已定型不再整理：

1. **无号批**：滚动条性能战役等约 35 条连续无号提交（2026-10 下旬）
2. **格式旁支**：`v4.1.3` 单发一条（bb41783）
3. **号段回退撞车**：a155R/R2 之后经无号批，新线从 a134 重新起号——a134–a142 与历史已占用的 a134–a147 撞段。两条线靠哈希可区分，账面撞号不再追溯修正

**自 a156 起统一执行本规则。**
