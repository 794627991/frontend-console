# 日志与错误覆盖评估（a657）

> 结论：前端/后端**常规错误覆盖率约 70%**，但有 3 个关键盲区：**退出原因**
> （本次「工具自杀」无法定位的直接原因）、**WebView2 渲染进程崩溃**、
> **Worker 内部错误**。以下全部按「不落盘、低 IO」约束设计。

## 一、已覆盖（核实到代码）

| 错误类型 | 落点 | 证据 |
|---|---|---|
| 后端未捕获异常（请求内） | backend_log.error + traceback | server.py errorhandler |
| API 异常请求（非 2xx / 写操作） | [api] 行 | `_log_api_outcome` |
| 后台线程未捕获异常 | backend_log | `threading.excepthook`（backend_log.py:914） |
| 子进程输出（claude worker / werkzeug / webview） | stdout/stderr Tee | backend_log.install |
| 前端 console.error | `/api/frontend_log` → [frontend] | index.html 内联 hook |
| 前端 window error / unhandledrejection | 同上 | 同上（字符打散已修） |
| 慢请求（>5s） | watchdog_dump.log（全线程栈） | src/watchdog.py |
| C 级致命崩溃（fatal signal） | crash_dump.log（faulthandler） | main.py:15-19 |

## 三、与「不落盘」约束的折中

1. 常规日志：继续全部驻内存（现状，10MB 环形缓冲）。
2. **仅异常退出**：写一个小文件 `~/.serialconsole_pro/exit_reason.log`（含原因、时间、最后 50 条内存日志摘要，<16KB，滚动保留 3 份）——一次崩溃一次写，IO 可忽略。
3. 崩溃 dump（faulthandler)已是现有行为，保留。

## 四、落地顺序建议

P0 三项（退出原因、Worker 错误、WebView2 崩溃）→ P1 四项（warn/资源/CSP/空 catch 规则）→ P2 视需要。


## 五、a662 落地说明

1. 退出原因审计（`src/main.py`）：托盘/API/用户关窗/清理/SIGINT/SIGTERM 统一记录；
   **非预期退出**写 `~/.serialconsole_pro/exit_reason.log`（含最后 40 条内存日志，
   超 64KB 轮转为 .1；正常退出不写）。
2. WebView2 心跳（`src/server.py` + `index.html`）：页面每 15s 上报，>60s 丢失
   记 `[ui] 页面心跳丢失`（纯内存，不落盘）。
3. Worker 错误上报（`monaco-bridge.js` WORKER_BOOT）：self.onerror /
   unhandledrejection → `/api/frontend_log`（5s 节流）。
4. 日志弹窗界面版本号已移除（导出/复制头部仍保留追溯版本）。


## 六、a663 修正（启动事故与合并）

- **事故**：a662 在 main.py 顶层新增 `atexit.register(_audit_exit)` 但漏了
  `import atexit` → 模块导入即 NameError，工具无法启动（py_compile 只查语法，
  查不出 NameError）。已由并行会话补 import，本批一并提交。
- **合并**：`_exit_reason/_audit_exit` 实现移入 `backend_log`（新增
  `set_exit_reason/audit_exit/_install_exit_hooks`），由
  `install_excepthooks()` 统一安装 atexit + signal 钩子；main.py 只保留薄封装
  转发——避免两套退出审计并存。
- **铁律（写入流程）**：凡改启动链文件（main.py/server.py/backend_log.py/
  index.html），提交前必须至少执行一次 `python -c "import src.main"`（或
  `--selftest`）；py_compile 不够。
