# 真机冒烟测试总纲（用户发起制）

## 定位

L0-L2（静态/启动/DOM）验证不了的只有一件事：**投影 → CLI → SSE → 渲染**整条真机链路。
冒烟用 1 条消息、约 30 秒，做发布前最低成本的保险。

**触发规则（用户定调）**：冒烟**不挂 git hook、不自动执行**，只在用户明确要求时发起。

```bat
rem 用户主动发起（AI 执行或用户自行执行）
python tests/regression/run_all.py --smoke

rem 或直接对 AI 说：「跑冒烟」——AI 按本总纲执行并回报
```

## 用例

| ID | 用例 | 步骤 | 断言 | 额度 | 耗时 |
|---|---|---|---|---|---|
| SMOKE-1 | 真机会话冒烟 | 新建会话 → 发「只回复两个字：收到」→ 等空闲 | 回复存在（`.h-msg.asst`≥1）、工作头「已工作」可见、busy 收敛 | 1 条 | ~30s |
| SMOKE-2（可选） | 工具链路 | 发「用 Bash 执行 echo hi，然后只回复 done」→ 轮询 | `.h-tool` 在 ≤5s 出现、终态徽章含「完成」 | 1 条 | ~40s |
| SMOKE-3（可选） | 切会话回归 | 新建空会话 → 切回冒烟会话 | 组数/正文数不丢、无重复 | 0 | ~15s |

默认只跑 SMOKE-1；用户要求「深度冒烟」时加跑 SMOKE-2/3。

## 执行与留档

- 结果自动追加 `测试报告.md`（节标题含 SMOKE）。
- 失败必须附：`window.__regErrs`、控制台异常、截图（`tests/regression/artifacts/<ts>/`）。
- 结束后切回用户原会话；测试会话由执行者负责删除（标题为测试消息的会话）。

## 判据

- SMOKE-1 FAIL = 阻断发布（真机链路断了，L0-L2 全绿也无效）。
- SMOKE-2 FAIL = 阻断发布（工具链是核心功能）。
- SKIP 仅允许「应用未运行」。

## 窗口使用约定（a656）

- 冒烟必须观察真实窗口的投影链路，属「用户发起制」；执行前告知用户。
- 冒烟之外的重复性验证（样式对比、静态检查、DOM 结构）一律 headless，
  见 `测试计划.md` §10。

## 不做什么

- 不做长会话/子代理/回滚/压缩（属 L3 专项，用户按需发起）。
- 不在 pre-push / post-commit 中自动触发（避免额度消耗）。

## 产品语义备注（a669 修正）

- **停止生成后，已有上下文的会话可以继续发送**（用户常用路径；a669 真机
  验证：续发的新回合正常显示「已工作」，不会被误标「已停止」）。
- 仅「**全新会话的第一条消息就停止**」时会话不可恢复（后端 400「会话已失效，
  请新建会话」）——属预期边界，不是功能缺陷。
- 相关回归：L3 H7-2（停止定格）、H7-4（停止后续发）。
