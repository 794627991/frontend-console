## 2. 分层与判据

| 层 | 名称 | 是否耗 CLI 额度 | 执行方式 | 判据 |
|---|---|---|---|---|
| L0 | 静态门禁 | 否 | Python 静态扫描（`test_l0_static.py`） | 挂载矩阵 0 缺失 / 动态取用 0 缺失 / 存取器完整 / 引入顺序 0 风险 |
| L1 | 启动自检 | 否 | CDP 连接运行中的应用 | 页面 0 exception、0 module 加载失败、挂载可达、存取器读写往返 |
| L2 | CDP DOM 驱动 | 否 | CDP 调用页面函数 + DOM 断言 | 选择器命中数量/文本/样式符合预期，步骤间 0 exception |
| L3 | 真实 CLI 交互 | **是** | CDP 发真实消息，轮询投影 DOM | 数据正确性逐字比对 + L2 级断言 |
| L4 | 竞态/破坏性 | 部分 | 连续快速操作 ×3 | 状态收敛、无孤儿 DOM/计时器/重复行 |

## 3. 环境

- 前端控制台运行中：主 UI `http://127.0.0.1:<port>/`，CDP 端口 9222（`src/main.py` 常开）。
- L3 需要可用的 Claude CLI（应用内会话自动化）。
- 测试通过 `src/devtools_cdp.py`（项目自带 CDP 客户端）驱动，无额外依赖。
- 测试会新建会话；结束后切回测试开始时的会话，不删除测试会话。

## 4. 执行顺序与额度预算

1. L0 → L1 → L2：全量，零额度，每次提交/合并前必跑。
2. L3：按组执行，预算约 15 条上行消息：
   - `H1`（消息/排队/引用）1 会话 / 约 5 条
   - `H2/H3/H4`（流式/工具/工作头）1 会话 / 约 4 条
   - `H5`（切换重建）复用已有会话往返
   - `H6`（子代理）1 会话 / 约 2 条
   - `H7`（回滚/中断/压缩）1 会话 / 约 3 条
   - `H8`（识图）1 会话 / 约 1 条（需图片）
3. L4：在 L2/L3 基础上各做一轮快速连续操作。

## 5. 通过标准

- **P0 全 PASS**（核心链路：发消息/工具/工作头/切换/子代理/回滚）。
- P1/P2 允许 SKIP，但必须在 `测试报告.md` 写明原因（环境缺失/需求变更）。
- FAIL 必须附证据（断言实际值 + 截图/异常栈）并建缺陷记录。

## 6. 留档规则

- 每次执行 `run_all.py` 自动向 `测试报告.md` **追加**一节：时间、HEAD、`_HG_VER`、各层结果。
- 用例 ↔ 脚本映射见 `用例明细.md` 的「脚本」列。
- 截图/日志落 `docs/modularization-regression/artifacts/<时间戳>/`。

## 8. 功能点约定（新增/修改功能时）

1. 先在 `用例明细.md` 增/改用例（ID、层、断言）；
2. 在 `tests/regression/` 对应模块加自动化（可自动化的必须自动化）；
3. 跑 `run_all.py --layers L0,L1,L2`，结果自动留档；
4. 不可自动化的项写明手工步骤与原因（SKIP 必须带理由）。

## 10. Headless 优先原则（a656，用户定调）

0. **默认 headless**：`cdp_lib.Page()` 默认启动独立 Chrome（打开同一后端，
   URL 带 `?regression=1`：禁用 pagehide 断开真实连接、禁用 recent 写用户
   config）。真实窗口模式为显式 opt-in：`REGRESSION_CDP_MODE=real`。
1. **能用 headless 验证的一律 headless**：静态检查、冷启动、样式/布局对比、
   DOM 结构断言优先用 headless Chrome（`boot_probe.py` / `style_snapshot.py`
   的页内切换模式），**不得在用户真实窗口做重复性/高频操作**。
2. **真实窗口只做必要验证**：L2 功能回归（需要真实后端状态/会话）与 L3 真机
   链路。执行前说明、结束后恢复（切回原会话、关闭测试 tab/面板）。
3. **样式/视觉类改动的标准验证**：规则守恒 + 页内 stylesheet 切换对比
   （同一 DOM，headless），part→part 对照排除采样噪声；不依赖真实窗口截图。
4. 任何测试若必须触碰真实窗口，先告知用户预期操作与时长；用户可随时叫停。
