## 〇、用户报告 Bug：切配置方案后模型不刷新（已修复）

**现象**：切了配置方案（设置 → 配置方案 → 应用），模型下拉还是旧网关的模型名，必须重启工具才刷新。

**根因两层**：

1. **后端缓存永不失效**：`claude_harness.py` 的 `available_models()` 用模块级 `_models_cache`，首次调用读 `~/.claude/settings.json` 后缓存，之后不再读盘。配置方案切换（`claude_default.py` `/api/claude/profiles/apply` 整份写回 settings.json）后：
   - `/api/harness/models`（模型下拉、/model 命令）返回旧模型映射；
   - `/api/harness/vision`（识图配置下拉）返回旧模型；
   - `_vision_needed()` / 多模态判定（👁 标记、识图会话拉不拉）按旧默认模型判断。
2. **前端缓存同样不失效**：`claude-harness.js` 的 `_HG.models` 在 harness tab 存续期只预取一次（模型 chip 点击 `if (!_HG.models)` 才拉、`/model` 命令同款），后端修好后开着的 tab 也不会重新拉。

**修复**（本次已做）：
- 后端 `available_models()` 改为按 settings.json 的 `st_mtime_ns` 失效缓存——文件变了自动重读，任何写 settings.json 的路径（配置方案切换、API 配置保存、用户手改）都覆盖。
- 前端模型菜单 chip 和 `/model` 命令改为每次打开重新拉 `/api/harness/models`（本地请求，无感），拉到的最新值也顺带刷新 `_HG.models`（会话列表 👁 标记、chip 默认模型显示同步用）。

## 一、高优先级问题

### 1. 临时调试代码遗留（两处，注释自称「用完删」）
- `web/js/claude-harness.js` `_histRender()` 尾部：每次历史重建都 `fetch('/api/_dbg')` POST 整段 flow DOM 结构 + computed styles——注释明写「临时诊断（组结构乱序排查，用完删）」。
- `src/server.py:126` `/api/_dbg` 调试落盘通道仍在，`STATE_DIR/harness_dbg.log` 持续增长。
建议：两处一并删除（属清理非功能改动，留待后续）。

### 2. 模型映射枚举键不一致：harness 漏了 FABLE
- `src/claude_default.py:298-303` 的映射键有 6 个：`ANTHROPIC_MODEL` + OPUS/SONNET/HAIKU/**FABLE**/FLASH；
- `src/claude_harness.py` `available_models()` 只枚举 5 个（含 FLASH，**漏 FABLE**）。
后果：settings.json 里配了 `ANTHROPIC_DEFAULT_FABLE_MODEL` 时，模型下拉不显示该模型（claude_default 默认铺设里没有 FABLE 键，但用户手配会踩）。

### 3. confirm 权限模式与 ask_user 超时语义冲突
- `confirm_bridge_text()`（claude_harness.py）要求模型「写操作前必须 ask_user 征得同意，用户拒绝不得绕过」；
- 但 `harness_ask_mcp.py` `_ask()` 超时 15min 后返回「用户长时间未作答，**请自行按最优方案继续**，并在回复中说明你的选择」。
后果：confirm 模式下用户离开 15 分钟，模型会被引导自行执行本该确认的写操作，绕过了权限模式的设计意图。建议：confirm 语义的提问超时应返回「未获确认，不得执行写操作」类文案（按会话 permission 区分，或 MCP 侧超时文案改为中性「用户未作答，请勿执行有副作用的操作」）。

## 二、并发与状态一致性

### 4. `send_message` 的 busy 竞态窗口
`claude_harness.py:798-802`：stdin 写成功之后才置 `self.busy = True`。Flask `threaded=True` 下两个并发 `/send` 都能在置位前通过 `if self.busy` 检查，两个 JSON 行交叠写入 stdin。前端有 busy 拦截，但 API 层裸调可复现。建议：busy 置位移到写 stdin 之前（或加锁）。

### 5. `_suppress_exit` 标志可能残留
`kill_proc(quiet=True)` 设置 `self._suppress_exit` 由 reader loop 的 finally 消费。但若 kill 时进程已经死透（`poll() is not None`，stdout 已 EOF、reader loop 早已跑完 finally），标志无人消费 → 残留。下一次**真正的意外退出**会被吞掉（用户看不到「会话进程已结束」）。触发链：会话内切模型两次且中间进程已自然退出。建议：设置前判 `proc.poll()`，已死就不设。

### 6. config.json 读改写丢更新
`_vision_save` / `_prompts_save`（claude_harness.py）是「读整份 config → 改一个键 → 原子写回」。单次写是原子的，但两方并发（如提示词保存与识图配置保存同时落）后写者覆盖前者。同一进程内都走 Flask 多线程，理论可复现。低概率，记录备查。

### 7. `_models_cache` 无锁双检
（已随本次修复顺手规避：mtime 校验路径同样无锁，最坏是重复读一次盘，无害。）

## 三、资源与生命周期

### 8. 前端 `_HG.cache`（会话 DOM 快照）无上限
`saveCache()` 每切会话存一份 innerHTML 到内存字典，删会话/关 tab 才清。几十个大会话来回切会攒出可观内存。已有「关 tab 卸载 flow」机制（`_hgFlowUnloadInit`）缓解单会话驻留，但快照字典本身无 LRU。建议后续加条数上限（如 10 条 LRU）。

### 9. 排队队列不随删会话清理
`_HG.queues[sid]` 在会话删除时不 pop，残留已删会话的排队草稿（内存微量）。

### 10. `_interrupt_async` 的 stdin 空写探活
`self._proc.stdin.write(b"")` 写 0 字节——一般无害，但对部分 CLI 可能被当作 EOF/空行事件；实际由紧接着的 kill 掩盖，记录备查。

## 四、语义/文案

### 11. 模型菜单标题文案过时
模型 popover 标题「模型（**有对话的会话需新建才生效**）」——v2.20 起已支持会话内直接切模型（`set_model` quiet 重启 + `--resume`），文案误导用户去新建会话。

### 12. 配置方案快照制语义风险（设计说明，非 bug）
`profiles/apply` 整份替换 settings.json：快照存下之后用户在 claude 自身（或设置面板）做的任何其他修改，切换时都会被快照覆盖。注释已声明该语义，前端也有提示；但「应用」没有「当前 settings 与快照有差异」的警告。可接受，记录。

### 13. `/api/harness/ctx` 尾扫 1MB 截断风险
单条 jsonl 行超 1MB（多图/巨附件）时尾扫块首行被截断跳过——已按注释「保险」处理，极端大会话可能拿不到最新 usage，环停在旧值。低危。

## 五、安全核对（结论：基本干净）

- **XSS**：用户可控文本渲染均经 `esc()` 或 markdown-it（`html:false`）——工具参数摘要、模型名、会话标题、附件名、提问卡片均覆盖；快照恢复（innerHTML）源自自身渲染产物。未发现注入点。
- **路径穿越**：`/api/harness/file` 防穿越校验（basename + realpath 前缀）正确；`upload` 的 name 取 basename + uuid 前缀。
- **绑定面**：Flask `127.0.0.1`、代理默认 `127.0.0.1`；TFTP `0.0.0.0` 与 httpfile `0.0.0.0` 属工具自身定位（局域网传文件），非 harness 范围。
- **MCP ask 通道**：`HARNESS_BACKEND` env 可覆盖后端地址，仅本机 claude 进程环境注入，无外部暴露面。
