### P0-4 `src/harness/v4hub.py:121-124` — 零产出不缓存 → 新会话首回合事件永久丢失　**新增**

```python
121:  if not feed.snap["rows"] and (s.log.last_seq or 0) > 0:
122:      log.warning("v4 主投影 hydration 零产出(不缓存) ...")
124:      return feed          # 不缓存，也不回收
```

- **机理**：新会话首回合 CLI 尚未落盘 jsonl → hydration 零行；但 `last_seq ≥ 1` → **每次 emit 新建 feed 又都不缓存**。于是该回合的 `turn_started / user_echo / ask / turn_hold / turn_complete` 全进一次性 feed，无人读；SSE 生成器闭包绑在其中一个一次性 feed 上永远收不到后续 ingest；等转写落盘终于缓存成功时，新 feed 的 `h = last_seq` 已越过这批事件 → **永久不可恢复**。
- **实测**：
  ```
  feed cached after 4 emits? False
  cached now? True
  state: {}
  rows: ['turn_header','user_input','marker']
  ask survived? False | turn_complete survived? False
  ```
- **用户可见**：**新开会话第一轮"一直工作中但主窗什么都不显示"**。这正是 a83 声称已根治的症状——a83 修的是键漂移，这是同症状的**第二条活路径**。
- **修法**：零产出必须有短 TTL 负缓存，或"有订阅者就缓存空 feed 并继续 live 摄入"；水化移出 emit 线程。

### P0-5 `src/harness/v4feed.py:360/741` + `_seqs` 非有序 bisect — 客户端静默丢一行　`未修，a95 放大`

- `self.snap["seq"] = seq` 无条件赋值（两处），落序 ≠ seq 序。
- a95 引入 bisect 游标后前提（`_seqs` 严格有序）被打破。
- **端到端实测**：
  ```
  snapshot seq 10 → frame(12) → frame after late 11: none
  server rows: [...,'m10','m12','m11','m13']
  client rows: [...,'m10','m12','m13']
  LOST on client: ['m11']       # 静默，不触发 snapshot
  ```
- **用户可见**：高并发下偶发"某条消息/某张工具卡凭空消失"，不重连不自愈。
- **修法**：`= max(...)` 且 `_seqs/_log` 有序插入；前端补 `toSeq > seq` 校验。
