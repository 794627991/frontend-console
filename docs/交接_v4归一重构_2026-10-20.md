## 1. 目标（用户原话，逐条即验收标准）

1. **所有数据先走后端落盘整合，前端只消费**；不允许「流式」与「重渲」两套方案并存，必须归一。
2. **UI 不变**（视觉/交互与现有 harness 一致）。
3. 屎山重构（原 28 JS / 15,419 行 + 20 py / 9,144 行）。
4. **子代理独立**：内容绝不进主窗口；活跃子代理必须像主窗口一样实时刷新（不允许只显示「工作中」无消息）；完成时结论必须正确渲染。
5. **前端动画平滑**，四项必须成立：用户消息出现 / 工作组头出现 / 正在执行动画出现 / **无占位气泡残留**。

## 2. 架构（v4 归一管线）

```
CLI stdout ──► session.emit() ──► log.emit()（锁内分配 seq，落存+广播）
                                      │
                                      ▼ persist-before-publish
                              v4hub.v4_ingest_main(s, env)
                                      │
                                      ▼
                    V4Feed.ingest(env)  ── 归约成封闭五操作 delta
                      row.appended / row.upserted / row.removed /
                      row.delta / state.updated
                                      │
                                      ▼
                 snapshot（= apply(deltas) 的产物，构造保证一致）
                 + delta log（保留 600 条）
                                      │
                    /v4/stream (SSE)：每 30ms 拉 frames_after(sent)
                                      → coalesce → 打一帧
                                      │
                                      ▼
                      前端 V4Store（唯一状态推进器）
                        ├ snapshot 帧 → 整体替换，绝不 merge
                        ├ deltas 帧   → 仅 fromSeq === 本地 seq 时 apply
                        └ 断档 → 不猜，携水位重订阅（服务端裁决 resume/snapshot）
                                      │
                                      ▼
                       V4View（唯一渲染层）：DOM = 投影的纯函数
                         placeRow / upsertRow / appendRow / removeSuffix
```

子代理：独立 topic `sub:<agentKey>`，独立 V4Feed + 独立 V4Store + 独立 V4View。
主投影里只有 `subagent` 行（无正文）；子内容物理上进不了主流。

## 4. 本批关键修复（含根因）

### 4.1 子代理内容泄漏进主窗口（**红线**）

- **根因**：`v4feed._reduce_cli` 完全没过滤子代理镜像事件，而 `session.py:1594` 有（两处不一致）。CLI 会把子代理事件镜像到主会话 stdout。
- **修复**：新增 `_is_sub_mirror(o)`，**分层口径**对齐 `sse.js`：
  - 业务事件（assistant/user/result）：`parent_tool_use_id or isSidechain`
  - `system` 事件：另加 `agent_id`（嵌套派发唯一标记）
  - 不做统一加宽，避免误杀主链正文

### 4.2 组头不收口 / 永卡「工作中」

- **根因**：`turn_complete` 缺失时（CLI 自发回合、hold 期）组头永不收口。
- **修复**：
  - `result` 帧兜底收口（`_reduce_cli` 原为 `pass`）
  - hold 期不收（`_held` 在 `turn_hold` 置位，`turn_complete` 与 `turn_error` **对称**清除，`_reset` 显式初始化）
  - `_ensure_header()` 组头懒建，四处入口兜底：`user_echo` / `assistant` / `subagent_started` / `turn_complete`
  - 组头在 `turn_started` 缺失时也能出现 → **「工作组头不出现」构造性消灭**

### 4.3 用户重发历史原话被静默丢弃

- **根因链**（reviewer 三轮挖出来的）：
  1. 去重用的是 `(kind, text[:200])` 全量内容匹配 → 任意间隔同文本都丢
  2. 加 ±5s 窗口 → 5s 内原样重发仍丢
  3. 想用「hydration 末条 user 行时刻」做边界 → `v4hub` 的时间戳解析 `int(str(ts)[:13])` 对 ISO 串恒抛异常 → 全部回落 0 → **边界是死代码**
- **最终修复**：
  - `v4hub._ts_ms()`：ISO-8601 优先，数字兜底（对齐 `subagent_projection._ts_ms`）
  - 去重改**单调上界**：`at <= hydration 最大时刻 + 2s`
    - 真实重复（同一条事件）：`at` 必然 ≤ 上界
    - 用户新发（即使文本相同）：`at` 必然 > 上界 → **不可能误杀**
  - 已知残留窄窗（已在代码注释与测试注释里显式标注，不伪装）：`at` 落在 hydration 末行 2s 内的同文本新消息仍会被当作重复；仅 feed 冷建那一次补放窗，极窄

### 4.4 子代理结论双份渲染

- **根因**：`SubagentHandback` 既落 `assistant_text` 行（时间线），又写 `state.final`（结论区）。
- **修复**：只写 `state.final` + `done`。结论单一真源，子 pane 由 `v4view._paintConcl` 渲染一次（`conclDone` 守卫）。

### 4.5 前端渲染层路线错误（v4 完全不可用的真因）

- **根因**：`v4render.js` 走「适配现有渲染基元」——调 `renderUser`/`grpEnsure`/`phStart`/`grpFinalize`/`_tlPlace`/`_hgDispatch`。这些基元自带 v3 状态机（`_HG.grp` 单活组、占位气泡、`_HG.asstText` 判据、行级 ts 账）。**两套状态机并行驱动同一棵 DOM**，必然出现：行重复/丢失、组头不出现、占位残留、徽章不写、思考段错乱。
- **修复**：新建 `v4view.js` 独立渲染层
  - 按 `row.kind` 直出 DOM，class 与旧 UI 逐一对齐（CSS 一条不改）
  - 组由 `turnId` 派生 —— 天然多组并存，**无认回逻辑**
  - **不预建占位气泡**：正文到达直接 append，构造性消灭「占位残留」
  - 组头/秒表/spinner 全部是投影状态的纯函数
  - 工具/子代理计数按 `rowId` 幂等（防 upsert 翻倍）
  - `rebuild` 保留 `conclEl`（子 pane 结论区不被整窗清场删掉）

### 4.6 `_subState` 未定义（P0 活 bug）

- **根因**：`subpane.js:1586` 调用 `_subState(tb)`，**全仓无定义**。第一个真实子代理 tab 就抛 `ReferenceError`，整个 2s 兜底 tick（`_subThinkPollTick`）自此中止 —— 404/408 自愈防线与 `_subTailFeed` 摘要轮询全部失效。
- **修复**：补三态函数
  - `final` = `tb.t.done`
  - `shell` = 无 `tb.t` 或 `rpN=0`（从未铺底）
  - `live` = 未定稿且已铺底
  - `none` = 无 tab

### 4.7 子 pane 与旧脚手架并存

- **根因**：v4 分支只接管了渲染，旧 `_subPaneScaffold` 建的空 `.hg-sub-turn` 仍留在窗格里 → 空壳。
- **修复**：v4 分支摘掉旧轮块，末尾重建 `.hg-sub-concl` 供 `state.final` 用；tab 标题走 `_subTabLabel`。

## 6. 设计约束（接手者必读，别翻案）

1. **DOM 是投影的纯函数**：同一 snapshot 渲染两次必须一致。渲染层不持有会话事实，只持有 `rowId → DOM` 索引。
2. **两条帧来源、一条管线**：snapshot → `rebuild()`；deltas → `applyDelta()`。历史与 live 走同一 `placeRow`/`upsertRow`，没有第二套渲染动作。
3. **不本地构造会话事实**：用户消息只来自后端回显；`overlay` 只含 `commandId`（不含文本、不渲染），只喂 watchdog。
4. **断档不猜**：`fromSeq !== 本地 seq` → 重订阅让服务端裁决，客户端没有结构猜测代码。
5. **旧渲染基元只复用无状态纯叶子**：`mdBubble` / `plainBubble` / `attChipsHtml` / `hgToolCard` / `statusBadge` / `_hgAgentRowBuild` / `_hgVisionCardBuild` / `_hgVisionResult` / `_hgIsExplore` / `_hgExp*` / `_hgAvaCls` / `esc` / `setBusy`。
   **禁止**再调 `renderUser` / `renderAsst` / `grpEnsure` / `grpFinalize` / `phStart` / `_tlPlace` / `_hgDispatch`。
6. **子代理内容物理隔离**：主投影过滤镜像事件；子内容只走 `sub:<agentKey>` topic。
