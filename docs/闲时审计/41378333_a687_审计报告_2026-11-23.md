## 发现明细

### B-1【低-中】`/api/data_dir` GET 每次请求全量深扫数据目录
- **文件**：`src/server.py:2829-2836`（`api_data_dir_get` 内新增段）
- **证据**：每次面板 GET 同步调用 `_dir_size(DATA_DIR)`，walk 全树求和，无缓存。
- **分析**：数据目录里 harness 会话/网页缓存/日志可达几百 MB、数万文件时，同步深扫会阻塞 Flask worker 秒级——打开设置面板（或前端轮询该接口的地方）会卡。深扫本身剪了 junction 环（`data_hygiene.py:81-96`，与迁移通道同款 `realpath` 剪枝，已核实无死循环风险），纯性能维度。注释标注「2026-11-23 用户令——面板只显示这一个数」，口径是用户拍板，故实现取舍不算违令，但**每次 GET 都重扫**是可以优化的部分。
- **建议**：加一层「目录 mtime + 上次结果」缓存，或深扫挪后台线程、接口先回旧值再刷新。

### B-2【低】深扫失败静默返回 0，与「目录为空」显示歧义
- **文件**：`src/server.py:2834-2836`
- **证据**：`except Exception: dir_total = 0`。
- **分析**：深扫异常（权限/路径失联）时面板显示「共 0 B」，用户可能误读为数据没了。低概率（`_dir_size` 内部已 `onerror` 跳过坏项，外层 except 兜的是 realpath 等极端异常），但 0 值语义双向歧义。
- **建议**：失败时返回 `null`，前端显示「无法统计」。
