## 一、P1 发现（9 条，验收前必须修）

### F1 [P1] xlsx 控制器取法错，定位/缩放/大纲/位置全部失效 —— C 路，主线已复核
- 位置：`web/js/office-engine.js:127`（`const c = viewer && viewer.controller;`）、`web/js/docview/xlsx.js:19`（`const ctrl = () => viewer && viewer.controller;`）
- 证据：vendor 实际类（`vendor/xlsx-engine/chunk-XUHSQ3GF.js:23879-23912`）公开成员只有 `element / getController() / setOptions / reload / subscribe / destroy`——没有 `controller` 属性；内部 `controller` 是闭包变量，经 `getController: () => controller`（chunk:23856）异步发布。另外 goTo 用的 `c.setActiveSheet(idx)` / `c.activateSheet(name)` 也不存在，真实接口是 `setActiveSheetIndex(index)`（chunk:2504）。
- 问题：两层取法全落空 → `handle.controller=undefined` → `show_in_viewer` 对 xlsx 全部定位失败、Ctrl+滚轮无反应（与 12.3 bug 9 自称「已修」的表现一模一样）、大纲空、位置/读取死路。**12.3 自称已修的 xlsx 缩放实际没修好**——修的是方法名（setZoomScale），没修取法。
- 建议：`viewer.getController()` 订阅方式拿控制器；表切换改 `setActiveSheetIndex`。

### F2 [P1] xlsx 默认可编辑、默认工具栏，D01「默认只读」没落实 —— C 路，主线已复核
- 位置：`web/js/office-engine.js:116-121`
- 证据：`createXlsxViewer(el, { file, ...(opts.extra || {}) })` 未传任何锁定参数；vendor 实现默认 `readOnly: requestedReadOnly = false`（chunk:2131）、`showDefaultToolbar = true`。注释「vanilla 视图默认就不可编辑」与库实现相反。
- 问题：违反 D01 用户令与 6.1.5；预览内存态可改出「用户改了格子、磁盘没变、AI read_document 读到旧内容」的静默分叉。
- 建议：传 `readOnly: true, showDefaultToolbar: false`。

### F3 [P1] restoreForSession 无调用点，切回会话文档标签永不恢复 —— C 路
- 位置：`web/js/docview/harness-pane.js:282`（定义）；`web/js/harness/subpane.js:351` 只有 `beforeReset`
- 证据：全库 grep 仅命中定义与挂载，无任何调用。
- 问题：违反 6.2.5；`_bySid` 里的记录是死数据，切回旧会话文档标签全部消失。
- 建议：`_subRestoreActive` 之后补调 `window.DocView.restoreForSession(sid)`。

### F4 [P1] 切会话不销毁文档实例：轮询/观察器/渲染器全泄漏 —— C 路
- 位置：`web/js/harness/subpane.js:364-369`（`_subReset` 清场循环）
- 证据：只清 `tb.tick`，不调 `tb.onDestroy()`，`_sub.tabs = {}` 整表丢弃；`onDestroy` 只在手动关单标签（panel.js:388）被调。
- 问题：每次切会话，打开着的 DocInstance 被自己的 4 秒轮询闭包钉住，ResizeObserver、pdf.js document、xlsx wasm/worker 全部存活，还会对已脱离 DOM 的面板自动重载。违反 11.F。
- 建议：清场循环补 `if (tb.onDestroy) tb.onDestroy()`（与 panel.js 同款）。

### F5 [P1] get_view 工具恒失败：MCP 发 POST，路由只收 GET —— B/D 两路独立同证
- 位置：`src/mcp_server.py:810-811`（`_doc` → `_post` 统一 POST）+ `src/doc_api.py:413`（`methods=["GET"]`）
- 证据：`_post` 用 `urllib` 发 POST，打 GET-only 路由必得 405，无捕获，每次返回「失败：未知错误 HTTPError」。测试只覆盖 GET 形态（test_doc_api.py:381/389 用 `client.get`），MCP 的 POST 链路从未被触达。
- 问题：六个文档工具缺员一个（6.5 表登记的工具）。8.1 该路由方法即 GET，MCP 层用错方法。
- 建议：`api_doc_view` 加 `methods=["GET","POST"]` 或 `_doc` 增加 GET 通道；补「MCP 工具函数 → Flask test client」形态的契约测试。

### F6 [P1] show_in_viewer 的顶层 path 参数被后端静默忽略 —— D 路，主线已复核
- 位置：`src/mcp_server.py`（`tool_show_in_viewer`：`body["path"] = str(path)`）+ `src/doc_api.py:275-322`
- 证据：`api_doc_show` 只读 `targets/note/seq`，从不读 body 顶层 `path`；302 行取 `targets[0].get("path")`——而工具 schema 里 targets 元素只有 `{anchor, quote}`，AI 塞不进 path。工具描述承诺「锚点不带路径时用它确定文档」，该承诺没有实现。
- 问题：纯位置锚点 + path 时退化为视图当前文档——面板开着别的文档就静默 show 到错误文档；面板没开任何文档时报「路径为空」。8.4/附录 B 的 path 语义落空。
- 建议：`api_doc_show` 补 `data.get("path")` 并纳入解析优先级。

### F7 [P1] 相对路径按错误进程的 cwd 解析 —— B/D 两路独立同证
- 位置：`src/doc_api.py:236-238`（`request_base_dir(): return os.getcwd()`）+ `src/mcp_server.py:752-757`（path 原样透传）
- 证据：设计 6.4.2 第 2 步预设校验发生在「每会话一个的 MCP 进程」（cwd=会话项目目录）；实际校验在全局单例的 Flask 后端进程执行，其 cwd 是工具目录/项目根。doc_store.validate_path 自己的注释还写着「进程 cwd 不可靠」——与 request_base_dir 的做法自相矛盾。
- 问题：AI 传相对路径按工具目录展开：要么 not_found，要么静默读到工具目录下同名文件。安装形态几乎必错。
- 建议：MCP 进程发送前按自己的 cwd 补成绝对路径，或随请求携带会话目录；至少工具描述改口「请传绝对路径」。

### F8 [P1] D04「一套引擎两处用」：docx/pdf 主界面未迁入统一引擎，偏离未声明 —— A 路，主线已复核

- 问题：D04 用户拍板「一并换」只兑现了一半（pptx/xlsx）。12.1 把收窄后的范围标为「完成」，12.2 偏离表五条均不含此项——偏离未如实声明。
- 建议：12.2 补偏离声明（「docx/pdf 主界面维持自有薄壳，迁出留 Step 4」），或后续提交真正迁出。
