## 发现明细

### A-1【低】死变量 `_cfg_had_before`：注释承诺的「只拦本来在、后来没了」未实现
- **文件**：`src/server.py:3262`（定义）、`src/server.py:3404-3409`（最终硬闸）
- **证据**：`grep -n '_cfg_had_before' src/server.py` 仅 1 处命中（定义行），全函数无引用。硬闸实现为无条件 `if not os.path.isfile(os.path.join(_st.TOOL_DATA_DIR, "config.json"))`。
- **分析**：3260-3261 行注释写「真正要防的是『本来在、迁移后没了』，由函数末尾的最终硬闸核对（R8-4）」，但硬闸并没有拿 `_cfg_had_before` 做比对。实际后果有限——`_save_config` 是锁内原子写，要么成功要么抛异常冒泡，几乎不存在「静默写失败」，所以「全新安装 + 无条件硬闸误拦」的窗口近乎为零。但语义已经漂移：未来维护者会误信注释以为硬闸带前置条件；或反过来把死变量当有用代码保留。
- **建议**：二选一——硬闸改为 `if _cfg_had_before and not os.path.isfile(...)`（与注释对齐），或删掉 3262 行死变量并修正 3260 行注释为「无条件核对」。

### A-2【低】`_selfheal_cfg` 无副本可恢复时 `.bad-<时间>` 留证每次启动重复堆积
- **文件**：`src/app_state.py:253-261`（最终留证段，重点 257 行）
- **证据**：config 坏且 `.bak`/镜像都救不了时，留证 `.bad-<时间>` 后返回 `{}`，**坏文件本体原地不动**。下次启动再次进入同一路径，再留一个新时间戳的 `.bad`。
- **分析**：时间戳到秒级，每次启动一个文件，长期运行的坏配置现场会堆积大量 `.bad-*`（且都会被迁移收回逻辑 R8-5 的 `config.json.bad-` 前缀匹配收走，进一步放大）。非数据风险，纯垃圾堆积。
- **建议**：留证前检查是否已存在同内容/近期 `.bad`（例如当日已有留证则跳过），或留证后把坏件同时改名为 `.bad` 使下次走 `FileNotFoundError` 路径。

### A-3【低】壳 `readConfigBool` 读残留 endpoint.json 不校验 boot_token
- **文件**：`electron/main.js:348-361`（`readConfigBool`，348 行起）
- **证据**：新增逻辑直接 `JSON.parse(fs.readFileSync(ENDPOINT_FILE))` 取 `tool_data_dir`，与后端-壳鉴权链（boot_token 匹配）不同口径，不校验新鲜度。
- **分析**：场景=工具目录整体挪位后启动失败（endpoint 残留旧位置的 tool_data_dir），再点 ✕，`close_to_tray` 会读旧位置的 config.json。影响面仅一个托盘布尔值，读不到时回落 `dft`，实害趋近于零。注释已自知「点 ✕ 一定在后端启动之后」的假设。
- **建议**：可不改；若要收口，读 endpoint 时顺带比对 boot_token 与内存态一致才采信。

### A-4【低】`.key/.crt/.pfx` 后缀进严格校验存在误伤面
- **文件**：`src/server.py:2739`（`_MIGRATE_STRICT_EXT` 定义）、`src/server.py:3107` 与 `src/server.py:3219`（两处使用）
- **证据**：根级文件按后缀判严格校验，数据目录根级恰好存在名为 `xxx.key`/`xxx.crt` 的非证书文件（如某些工具的数据文件）时，拷贝失败会中止整个迁移。
- **分析**：方向保守——误伤只会「拒绝迁移」而不是丢数据，与漏拦（私钥静默丢失）相比是正确的取舍侧。仅记录，供排障时知晓。
- **建议**：维持现状；若未来出现误伤反馈，可对私钥类改为「白名单文件名 + 后缀」双条件。

### A-5【记录】最终硬闸失败路径的全局状态半切换
- **文件**：`src/server.py:3404-3409`
- **分析**：走到硬闸失败 `return 500` 时，`_st.DATA_DIR/STATE_DIR/LOG_DIR` 已在 3263-3265 切换为 target，报错文案「未完成切换」与内存态不符。数据实际已在新目录、config 是唯一缺件，重启后 `_selfheal_cfg` 自愈链接管。路径极端罕见（仅 `_save_config` 成功后 config 又消失的现场），仅记录不要求修。

### A-6【记录】迁移通道丢弃用户自建的 reparse point（junction）
- **文件**：`src/server.py:2723-2727`、`src/server.py:2770-2774`（剪枝）；`src/server.py:3399`（形态① rmtree）
- **分析**：子目录与根级文件通道均剪掉 reparse point 不拷；形态① `shutil.rmtree(old_data_dir)` 在 Python 3.8+ 对 junction 只删链接本身不跟进（已核实本项目 Python 3.14），指向的外部数据不丢，但链接本身迁移后消失。属于「数据目录里的 junction 不属于被管理的用户数据」的合理取舍，记录在案。
