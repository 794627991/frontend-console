## 1. 用户实锤三问题的最终方案

### 问题 1 · 测试脚本不该计入审计行数

`src/harness/audit.py` — `_audit_is_test_path()`

三级判据（大小写不敏感）：
1. `os.path.normpath` 消 `..`/`.` → 路径中含测试目录段（`tests` / `testing` / `test` / `__tests__` / `e2e` / `fixtures`）
2. 文件名前缀：`test_` 全仓库；`_probe_` / `_scan_` / `_stress_` 等探针组**限 `tools/` 父目录或根级单文件**
3. 文件名后缀：`_test.py` / `.test.js` / `.spec.ts` 等

**关键设计决定（踩过的坑）**：曾把「仓库根」锚定为运行代码所在目录（`_SRC_DIR` 上一级），实测导致 worktree / 用户项目 / 发布版 exe 下的 `tests/*.py` 全部计 501 行——豁免整体失效。已改为**与根无关**，只靠 normpath + 目录段。

`specs/` 目录**不豁免**（本仓库无 RSpec 证据，`specs/` 是文档）；纯文档后缀（`.md/.txt/.rst` 等）由既有 `_AUDIT_DOC_EXTS` 单独豁免。

### 问题 2 · 事中闸必须中途拦，不能只事后咬

`src/harness/session.py` + `src/harness/routes.py` + `src/harness/roles.py`

根因两层：
- 表层：`start()` 注入 hook 的条件是 `not st[2]`（只 light），而 `_audit_settle` 的设计档不看 strong → mid 形态只事后咬
- 深层：即使去掉 strong 判断，注入条件仍取 `design_limit()` 的**启动瞬间快照**——会话启动后改配置、或启动时形态被误判成 heavy，钩子就永久缺席

现在：只要 `_audit_state() is not None`（roles 开 + audit_mode≠off + 非 heavy）**就注入**；挡不挡、何时挡由 `/audit_gate` 每次调用实时判定。

配套（否则闸一开就死锁）：`roles.py` 的 mid 形态原来只装 `reviewer.md`，但闸会指路「先派 designer」——mid 环境里 designer 不存在，Task 派发报错且无法满足。已让 mid 同时装 `designer.md`，`ensure_roles_ready` 的 need 同步补，mid 引导词补设计线段。

### 问题 3 · 停止子代理后胶囊仍显示运行

根因四层，分布在四条链路上：

| 层 | 缺陷 | 修法 |
|---|---|---|
| 信号接入 | 停止通知的 `<task-notification>` **不带 `<tool-use-id>`**，只有 `<task-id>`（=agentId）；`_emit_task_mirror` 开头 `if not tid: return` 直接丢弃 | task_notification 缺 tid 时按 agentId 继续走 |
| 状态词表 | `stopped` 被归入 `interrupted`，而 `interrupted` 在本模块是 **mtime 启发式猜测**（转写停更=以为中断）；前端明确「interrupted 不落定」→ 主动停止的代理刷新后又变回运行中 | `_status_from_notify` 把 `stopped` 单列（确定性事实），`interrupted` 只留失联 |
| 投影终态 | `ok=False` 落 `failed`（红叉）；或翻 `success`（被摘要/统计误读成「有交付」） | 用 v4proto 词表已有的 `cancelled` |
| V3 前端 | **v4 默认关闭**（`v4main.js:11`），用户实际走 V3 管线 `sse.js`；无 tid 的收口写在了 `else if (tid && !_shBg)` **内部** = 死代码 | 提到守卫块之外成为顶层分支，按 agentId 定位 |
