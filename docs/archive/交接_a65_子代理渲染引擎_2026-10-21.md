# a65 交接：v4 子代理渲染引擎 + 主子隔离根治（2026-10-21）

> 前置：a64（同日，随本版一并提交）——v4 子页 EventSource 泄漏修复。
> 用户两条验收标准（原话）：①子代理别和主窗口混了；②打开子代理必须像
> V3 一样无条件显示内容。本版两条都做成**结构性保证**，不靠时序运气。

## 1. 根因（实测取证，非推测）

在 54648 实例上用 `__v4dbg` 埋点实锤的完整因果链：

1. **混窗**：子 bridge 的 `_rebuild` 调 `_histRender`（主窗整窗渲染器）——
   子快照的 6 行直接刷进主窗 flow，`_HG.histAll/histCursor` 被子代理的账
   覆盖（a62 只挡了 bridge 里的显式赋值，`_histRender` **内部**的
   `_HG.histAll = lines`（histcache.js:94）没挡住）。子代理页一开，主窗
   就被替换成子代理内容。
2. **子页空**：渲染落点全在主窗，窗格容器本体只剩结论 div——永远空。
3. **4 秒风暴**：v4 分支从不设 `tb.rpN` → `_subState` 恒 `shell` →
   `_subThinkPollTick` 每 3s 调 `_subEnsure` → `_subReplay` → 重开 store
   → 新快照再刷主窗（a64 前还每轮泄漏一条连接）。

## 2. 修复架构

**数据=投影（v4），渲染=V3 subpane kit（subpane.js 现成件），落点=窗格容器。**

### 前端
| 文件 | 改动 |
|---|---|
| `v4bridge.js` | 新增子模式渲染引擎（`_subRebuild/_subAppend/_subApplyOne/_subFinish/_subFallback` 族）：复用 `_subPaneScaffold/_subTl*` 现成件，快照铺底+delta 实时续流+秒表+定稿+结论区；双源查重锚（hgRp/raw/tuid）保证快照/兜底/delta 三路喂入幂等；**主窗函数（_histRender/_hgRowAdd/renderToolUse/setBusy）在子模式结构性不可达** |
| `v4main.js` | `subOpen(el, agentKey, {tid,type,desc})`——bridge 需要 tid 查 tab、type/desc 建脚手架 |
| `subpane.js` | v4 分支瘦身为一次 `subOpen` 调用；`window._sub` 显式挂（const 不上 window，bridge `_g('_sub')` 此前恒空=快照被静默丢弃的隐形坑）；`_subState` v4 感知（健康源=store 连接，非 V3 tick）——4s ensure 循环构造性消失 |

### 无条件显示（三级兜底，打开必有内容）
1. v4 子投影快照（watcher 喂/转写 hydrate）；
2. 快照零行 → `/api/harness/subagent_replay`（V3 已验证数据源，**同一渲染器**铺底，铺后强制重订阅让服务端快照整体接管，无双源重复）；
3. 双 miss → 「未找到该子代理的转写记录」注记 + 档案结论（`agents.result`，冷同步补 brief）；
   运行中代理转写晚到 → 「转写尚未生成——实况跟随中」+ watcher 按需 hydrate 续流。

### 后端
| 文件 | 改动 |
|---|---|
| `v4feed.py` | ①`_is_sub_mirror` 补 `isMeta`（设计 §5.2/sse.js 同口径）②`feed_jsonl_line` uuid 去重（hydrate/watcher 并发双喂闸）③行时刻改用行自身 `timestamp`（原喂入时刻=全文件同毫秒，轮时长恒 0 秒） |
| `v4hub.py` | `v4_main_has/v4_sub_has/v4_sub_hydrate`——watcher 按需冷建子 feed（V3 模式恒不触发，行为不变） |
| `subagent_watch.py` | feed 不在且会话有 v4 主投影 → 转写首行出现即全量 hydrate（本轮增量跳过防重复） |
