**行号会漂移。** 开工前先 `git log --oneline -1` 核对基线。基线前进过就以实际代码为准，并在改动说明里注明哪些行号对不上。不要照着过期行号盲改。

- 「已读」：作者直接读过该文件该行，可信。
- 「调研报告」：来自只读调研 agent 的报告，行号在 v4.0.0 树上复核过，但作者没逐行重读，引用前自己扫一眼。

**实施约束速查**（`AGENTS.md` 的全文优先，这里只列和本任务直接相关的）：

## 2. 背景：两边的现状

### 2.1 我方现状

**现有四条预览链**都在 `web/js/office-viewer.js`，打开在主界面标签页里：

| 类型 | 现有实现 | 问题 |
|---|---|---|
| PDF | pdf.js，虚拟化、全文搜索、书签目录 | 没有明显问题，是最强的一条 |
| DOCX | docx-preview，只读，有大纲 | 没有明显问题 |
| XLSX | SheetJS + 自研网格，可编辑、算公式、存回原文件 | 用户评价「效果极差」 |
| PPT | 本机 PowerPoint 通过 COM 转 PDF，再走 PDF 链 | 慢；没装 Office 的机器直接打不开；依赖会后台启动 PowerPoint |

**harness 会话里看不到文档。** 聊天流和工具行里的文件路径只是文本，没有点击打开的链路。AI 生成了一个文档，用户得离开会话页，用拖拽或最近打开才能看。

**本机环境**（实测）：

- 没装 OnlyOffice Document Server。默认安装目录不存在，四个探测端口都无响应。「全功能编辑」按钮点了只出安装指引。
- 装了 Microsoft Office，Word、PowerPoint、Excel 的 COM 都已注册，所以现有 PPT 转换链在本机能用。

### 2.2 ZCode 的做法

以下是对 ZCode v4.0.0 的调研事实，行号见第 4 章。

**预览面板不依赖任何外部程序。** 面板用纯 JS 库渲染，整个运行时里对 `qpdf`、`pandoc`、`soffice` 和子进程零引用。四种文档全部只读，没有编辑回写，文档里明确把「Office 文件编辑/保存」标为不提供。

**AI 的文档能力分两层。**

- 面板工具负责「和用户一起看文档」：`open_document`、`show_in_viewer`、`read_document`、`search_document`、`get_view`、`capture_view`。
- 面板之外的处理（转换、提取、编辑、生成）走 skill，skill 再调用预装工具。

**预装工具是五个，都只给 AI 用。** qpdf、Pandoc、Poppler、LibreOffice，以及一个 Python（入口名 `zcode-python`）。装在用户目录下，不要管理员权限，不随安装包，由后台按清单和 SHA-256 从 CDN 下载。启动 AI 时把工具目录放到 PATH 最前面。

| 工具 | 谁调用 | 做什么 |
|---|---|---|
| Poppler | 产品代码直接调 | 给 AI 的 Read 工具用：`pdfinfo` 取页数，`pdftoppm` 把 PDF 页转成图 |
| Pandoc、qpdf | 只出现在 skill 文档里 | 教 AI 通过命令行调用 |
| LibreOffice | skill 脚本以子进程调 | 转 PDF、重算表格公式、PPT 转换 |
| Python | 所有文档 skill 的脚本 | 解释器 |

**文档 skill 分两类。**

- 面板说明：`docx-viewer`、`pdf-viewer`、`xlsx-viewer`、`pptx-viewer`，共 4 个小文件。
- 生产 skill：`docx`（43 文件）、`pdf`（42 文件）、`xlsx`（28 文件）、`pptx`（5 文件），合计约 118 个文件、2.3MB、4.4 万行。

### 2.3 差异对照

| 方面 | ZCode | 我方现状 | 本次目标 |
|---|---|---|---|
| pptx 渲染 | `@aiden0z/pptx-renderer` 1.2.4，纯 JS | PowerPoint COM 转 PDF | 同版库 |
| xlsx 渲染 | `@extend-ai/react-xlsx` 0.16.0（React 组件 + wasm） | SheetJS + 自研网格 | 同引擎的无框架入口 0.24.1，见 6.1.2 |
| docx 渲染 | docx-preview 0.4.0 | docx-preview，版本待核对 | 保持 |
| pdf 渲染 | pdfjs-dist 5.4.296 | pdf.js，版本待核对 | 保持 |
| 编辑 | 全只读 | xlsx 可编辑；OnlyOffice 可选 | 只读；编辑只走 OnlyOffice |
| 会话内预览 | 右侧面板，每个文档一个标签 | 无 | harness 分屏文档标签 |
| AI 打开面板 | `open_document` 等工具 | 无 | 五个工具 |
| 聊天流文件路径 | 可点，按扩展名路由 | 纯文本 | 可点 |
| 文档处理 | skill + 预装工具 | 无 | 搬 skill + 文档运行时 |

**一处做不到逐字对齐的地方**：ZCode 用的 `@extend-ai/react-xlsx` 0.16.0 只有 React 组件形态，我方前端没有 React 也没有打包器。同一家的新版 0.24.1 才提供无框架入口（`/vanilla`），内部用 preact，官方文档写明「vanilla 入口不需要 React」。所以 xlsx 只能做到「同引擎、不同版本和入口」。这一点用户已知悉。

#### 4.2.1 docx：段落编号与定位

这是整个功能里最容易做错的一块。

**编号规则**在 `OR/src/adapters/parse/docx.ts:145-180`，只遍历 `w:body` 的直接子级：

```ts

else if (tag === "w:tbl") { /* at: `t:${tables.length + 1}`，只取 w:tr/w:tc 文本，不递归段落到 paragraphs */ }
else if (tag === "w:sdt") { walk(kids(child(node, "w:sdtContent") ?? {})); }
else if (tag === "w:customXml" || tag === "w:smartTag") { walk(kids(node)); }
```

| 情形 | 规则 | 位置 |
|---|---|---|
| 计入 `p` 序号的 | `w:body` 直接子级的 `w:p`，以及 `w:sdtContent`、`customXml`、`smartTag` 里的段落 | `:145-180` |
| 空段落 | 计入，输出 `[p:N] (empty)` | `:129` |
| 表格内的段落 | 不计入 `p` 序号。表格整体是 `t:N`，单元格文本把各段用换行拼接 | `:107-120` |
| 列表项 | 就是普通 `w:p`。有 `w:numPr` 或样式名以 `list` 开头时输出前缀 `- ` | `:162`、`:132` |
| 修订 | `runText` 跳过 `w:del`、`w:delText`、`w:instrText`；`w:ins` 不跳过，插入的文本计入 | `:94-101` |
| 批注、altChunk | 解析器不读。渲染时用 `renderComments: false`、`renderAltChunks: false` 不渲染 | `DocxView.tsx:142-144` |
| 文本框 | 文字并入宿主段落，不单独编号 | `:102` |

**渲染选项**在 `OR/ui/viewers/DocxView.tsx:132-146`，照抄：


**注意：`p:N` 到页面元素不是靠计数对应的，是靠文本对齐。** 流程如下。

1. 解析结果里带一份 `blocks: [{ at, text }]`，`text` 是归一化后截到 400 字符的块文本（`docx.ts:231-234`）。
2. 面板收集 `section.office-docx > article` 下的 `P`、`H1` 到 `H6`、`TABLE`（`DocxView.tsx:167-180`）。`HEADER`、`FOOTER`、`OL`、`UL` 只有在没有子元素时才跳过，否则照样递归。


4. 之后用 `[data-at="p:N"]` 查询。`t:N/rRcC` 先找到表，再取 `rows[row-1].cells[col-1]`（`DocxView.tsx:38-54`）。

对不上的元素不标注，返回 `null`。对齐时在前向 6 个块内查找，渲染器多出来的元素靠这个重新同步（`align.ts:22`、`:41-58`）。

#### 4.2.7 给模型看的返回文本

`describeSnapshot` 在 `OR/src/adapters/server.ts:79-93`，`describeDocument` 在 `:61-77`。**注意不在 `wording.ts`。**

缩进是两个空格乘以 `level - 1`，后面接 `- `，锚点与 label 之间两个空格。大纲超过 60 条时加一行 `  … N more`。没有文档时是 `The <TITLE> viewer has no document open.`

| 类型 | 清单标题 | 行的样子 | 最后一行 |
|---|---|---|---|
| xlsx | `Sheets:` | `- model.xlsx#Revenue  Revenue (A1:E9)` | `Locations: Sheet, Sheet!A1, Sheet!A1:D20 (quote names with spaces: 'Q3 data'!A1).` |
| pptx | `Slides:` | `- deck.pptx#slide:2  Timeline` | — |
| pdf | `Outline:` | `- paper.pdf#page:2  Method` | — |

**`read_document`**（`server.ts:218-228`）。首行是 `路径#定位 (类型名, revision r)`，空行，正文或 `(no text)`，空行，尾行是 `[end]` 或：

```text
[more: call read_document with anchor "report.docx" and cursor 37]
```

**块的前缀写法：**

- docx：`[p:14] 正文`、`[p:3] ## 标题`、`[p:5] - 列表项`、`[p:9] (empty)`、`[t:2]` 后接 markdown 表。定位到单元格时是 `[t:2/r1c3] 文本`。
- xlsx：`Revenue rows 1–25`，可能带 `(columns F–Z omitted; read a narrower range)`，后面接 markdown 表，表头是列字母，首列是行号，最后是 `Formulas:\nE2: =SUM(B2:D2)`。整表读时是 `## Sheet Revenue (A1:E9)`，带 `(N more rows; read Revenue for all)` 和 `Merged cells: …`。
- pptx：`## Slide 2: Timeline`、`[shape:5 text "标题 1"] 正文`、`Speaker notes: …`。
- pdf：`## Page 3` 后接页文本。

**cursor**（`model.ts:65-84`）：以单元下标计数，从 0 起。docx 一个单元是一个块，xlsx 是 25 行，pptx 是一张幻灯片，pdf 是一页。按 UTF-8 字节 24KiB 的预算累加，单元之间用两个换行连接。`next` 是下一个没读的下标，读完是 `null`。单个单元超预算时截断并加 `[… truncated; read a narrower location to see the rest]`。

**`search_document`**（`server.ts:243-250`）：

```text
2 matches for "growth" in report.docx:
- report.docx#p:6  …revenue grew by 12 percent compared…
```

没有命中是 `No matches for "…" in <path>.`。片段取命中前后各 60 字符，两端截断时加 `…`（`model.ts:55-59`）。

#### 4.2.8 其它解析器

- 分发是 `PARSERS[kind](bytes, path, pdfAssets)`，`bytes` 是 `Uint8Array`，只有 pdf 用第三个参数（`OR/src/adapters/parsers.ts:11-22`）。
- **xlsx**（`parse/xlsx.ts`）：
  - 先做 zip 炸弹检查，解压总量超过 512MiB 就拒绝（`parse/ooxml.ts:91-111`）。
  - 使用范围取 `sheet.dimensions` 且实际行数非零（`:66-70`）。
  - 合并单元格的非主格输出空串（`:46`）。
  - 公式没有缓存值时标注 `→ (not calculated in file)`（`:54`）。
  - 每个单元 25 行、最多 60 列；整列请求裁到使用范围（`:178-182`）。
- **pptx**（`parse/pptx.ts`）：形状取自 `p:sp`、`p:pic`、`p:graphicFrame`、`p:grpSp`、`p:cxnSp`，id 和名称读 `p:cNvPr`（`:69-128`）。组合形状只列成员，自身不输出（`:156`）。备注取 `placeholder="body"` 的形状（`:130-143`）。
- **pdf**（`parse/pdf.ts`）：最多索引 3000 页（`:36`）。页文本是 `item.str` 加上换行标记处的换行，去掉行尾空白，再过 `normalizeCjkCompat`（`:69-74`）。
- **图片在文本里的表示**：pptx 是 `[shape:7 picture "名称"] (image: 描述)`，没有描述时是 `(image)`（`:87-95`），图表是 `(chart)`（`:106-113`）。docx 和 xlsx 没有图片占位。pdf 没有文本层时是 `(no extractable text; the page may be scanned)`（`:108`）。

#### 4.2.12 用原生 JS 实现时最容易踩的坑

调研方基于读到的代码事实列的 15 条，每条都有依据。

1. **高亮接口可能不存在，而且会静默失败。** `CSS.highlights` 或 `Highlight` 缺失时 `paintRanges` 直接返回，没有高亮也不报错（`dom.ts:200-212`）。样式 `::highlight(office-reveal)` 要自己写（`panel.css:1065-1075`）。
2. **不能用 `scrollIntoView`**，它会连带滚动所有祖先（`dom.ts:214-241`）。
3. **docx 两端的文本处理必须一致。** 解析端跳过删除的修订和域代码（`docx.ts:94-101`），面板关掉 `renderChanges` 和 `renderAltChunks`（`DocxView.tsx:142-144`）。对齐用的是去空白加小写，块文本截到 400 字符（`align.ts:3`、`:44`）。改任何一边的选项或截断长度，`data-at` 就会错位。
4. **docx-preview 的 `renderAsync` 不能取消**，只能用一个活动标志丢弃过期结果（`DocxView.tsx:127`、`:148`、`:160`）。
5. **react-xlsx 的 worker 定位依赖补丁**（`build.mjs:92-129`、`XlsxView.tsx:24-37`）。我方整目录搬运后不需要，但要保证 `xlsx-worker.js` 与入口 chunk 在同一目录。
6. **xlsx 的 wasm 要先备好。** ZCode 是经 `setWasmSource(bytes)` 传字节。我方用默认加载器即可，但要确认 wasm 文件与 chunk 同目录。
7. **pdf 的中文字体链靠改 pdf.mjs 源码**（`build.mjs:135-150`），换版本会失效。我方 pdf 链不动，不涉及。
8. **pdf 要自己管 worker 和资源加载**（`PdfView.tsx:54-64`、`:38-52`、`:159-162`），沙箱的 CSP 要放行 blob 的 worker 和脚本与 `wasm-unsafe-eval`（`OR/scripts/e2e.mjs:55-69`）。我方没有 CSP，不涉及。
9. **pdf 文字层的 `Range` 会失效**，缩放会重建文字层，必须在新层上重新查找（`PdfView.tsx:241-253`、`:394-409`）。
10. **pdf 两端的文字归一要相同**，解析端和面板都对 `str` 做 `normalizeCjkCompat`（`pdf.ts:74`、`PdfView.tsx:69-77`），少一边 `quote` 就对不上。
11. **pptx 的形状高亮不在渲染出的 DOM 里**，依赖库的 `node.id` 与 `p:cNvPr` 的 id 严格相等（`PptxView.tsx:299`）。覆盖层要放在被缩放的宿主内，线宽要除以缩放比（`panel.css:1222-1226`）。
12. **xlsx 没有单元格 DOM**，高亮只能走样式回调（`XlsxView.tsx:116-153`）。
13. **三种文档的缩放机制各不相同**：docx 用 CSS 的 `zoom`（`DocxView.tsx:435`），pdf 用 viewport 的缩放，pptx 用 `transform: scale()`（`PptxView.tsx:135`）。凡是依赖 `getBoundingClientRect` 的标注代码，三种要分别测。
14. **截断可能切坏字符。** 所有截断要走 UTF-16 代理对安全的 `cut`，发给模型或宿主的文本要走 `wellFormed`，否则代理对被切开后整个请求会被拒（`OR/src/domain/text.ts:1-7`）。
15. **工具结果会重放。** 面板用 `reveal.seq > lastRevealSeq` 去重（`OR/ui/main.tsx:251-253`）。解析缓存按大小加修改时间判断是否复用（`documents.ts:52-67`）。

### 5.2 设计原则

| 编号 | 原则 | 理由 |
|---|---|---|
| P1 | 一套渲染引擎，主界面标签页和 harness 分屏两个宿主 | D04。渲染逻辑不能依赖某一个宿主的状态对象 |
| P2 | 锚点语法、工具名、参数、返回文本的格式照抄 ZCode | D01、D06。AI 看到的行为与 ZCode 一致，skill 里的说明也能直接对上 |
| P3 | 文档只在前端解析一次，结果回传后端 | 见下 |
| P4 | 文档工具复用现有的资源清单、红条和安装界面，不另起一套状态与面板 | D09、D10。用户 2026-11-25 补充红条可以复用来引导 |
| P5 | 能复用的不带，能离线预置的不联网装 | D08、D14 |
| P6 | 分屏里凡是「这是不是伪标签」的判断，改成按标签上的属性判断 | a693 接入 AI 浏览器时这类硬编码枚举有多处，是漏改的高发区 |

**P3 的理由。** ZCode 在后端解析文档，是因为它的面板跑在沙箱里读不了文件。我方没有这个约束。放在前端解析有三个好处：

- 定位靠的是「解析出的块文本」和「渲染出的 DOM」对齐（4.2.1）。两边都在前端，用的是同一份字节，规则改一处就够。
- pdf 的 `quote` 要和 pdf.js 的文字层一致才能高亮。换一个解析器提取文本，空格和字符顺序就可能对不上。
- 后端是 PyInstaller 冻结的 exe。要在后端解析，要么把 python-docx、openpyxl 这些库再打进一份，要么每次起子进程调 `docenv` 里的 Python。都不如前端直接解析。

代价是依赖前端在线。前端不响应时，工具要在超时后给出明确的中文错误（6.4）。

### 5.5 三条主要数据流

**一、AI 打开文档并定位**（`open_document`、`show_in_viewer`）

```
AI ──MCP──► mcp_server ──POST /api/doc/open──► 后端
                                            校验路径，登记 req_id，开始等待（上限 30 秒）
                                            ──SSE ui_action: doc_open──► 前端
前端：切到 AI 会话页，展开分屏，激活 AI 文档标签
      拉字节，解析，渲染，定位
      ──POST /api/doc/report_open──► 后端（带大纲、分页文本）
后端：唤醒等待，返回 describeDocument 文本
AI ◄──MCP 结果（大纲与可用的位置写法）──
```

`show_in_viewer` 多一步：前端定位完成后回传「定位到了哪几个」，后端把它写进返回文本。

**二、用户点聊天里的路径**

```
点击 ──► _hgFlowClick ──► DocView.openInHarness(path, { by: 'user' })
                            不经后端等待，直接在分屏开一个用户文档标签
```

**三、AI 读与搜**（`read_document`、`search_document`）

```
AI ──MCP──► 后端查索引缓存
            命中且 revision 没变 ──► 直接从缓存的分页文本里切页或搜索，返回
            未命中或已变 ──► 先走一遍流程一让前端解析并回传，再服务
```

### 5.6 需要用户本人操作的环节

## 6. 详细设计

### 6.1 渲染引擎

本节落实原则 P1：引擎不依赖任何一个宿主的状态对象。

#### 6.1.1 对外接口

```js
// 挂到一个容器上，返回一个文档实例
const inst = DocView.mount(container, { path, kind, host: 'main' | 'harness' });

inst.path; inst.kind;                 // kind: 'pdf' | 'docx' | 'xlsx' | 'pptx' | 'image'
inst.ready;                           // Promise，解析与首屏渲染完成后兑现
inst.info;                            // { path, kind, title, bytes, revision, units, outline }
inst.locate(anchor);                  // 滚到锚点所指位置。返回 { found, at }
inst.reveal(targets, note, seq);      // show_in_viewer 用。滚到第一个，高亮全部，显示说明条
inst.find(quote);                     // 面板内查找
inst.viewState();                     // { path, kind, at, selection: { text } }
inst.reload();                        // 重新加载（文件变更横幅的「重新加载」）
inst.destroy();                       // 释放：停轮询、销毁渲染器、移除监听
inst.on('changed' | 'location' | 'select' | 'error', cb);

// harness 分屏用
DocView.openInHarness(path, { at, by: 'user' });   // 开一个用户文档标签
DocView.agentOpen(req_id, path, at);               // 由 sense.js 在收到 doc_open 时调
DocView.agentShow(req_id, targets, note, seq);     // 由 sense.js 在收到 doc_show 时调
DocView.restoreForSession(sid);                    // 切回会话时恢复标签记录
```

每个格式的渲染器实现同一组内部方法，由 `core.js` 驱动：

```js
{
  parse(bytes, ctx)          // 产出 { outline, units, blocks? }，写入实例
  render(root, ctx)          // 首屏
  goTo(locator)              // 滚动到位置
  highlight(targets)         // 高亮，可选带 quote
  find(quote)                // 返回是否找到并滚过去
  viewState()                //当前位置与选区
  destroy()
}
```

`units` 是分页文本的单元数组，供 `read_document` 用。格式见 4.2.7。

#### 6.1.3 docx

**渲染。** 选项照抄 4.2.1 的那段。

**解析。** 用已有的 `vendor/docx-preview/jszip.min.js`（全局 `JSZip`，3.10.1）解出 `word/document.xml`，用 `DOMParser` 解析，按 `OR/src/adapters/parse/docx.ts:145-180` 的规则遍历 `w:body` 的直接子级，产出两样东西：

- `blocks: [{ at, text }]`，`text` 是归一化后截到 400 字符。给定位对齐用。
- `units`，每块一个单元，带前缀。给 `read_document` 用。

**定位。** 照 4.2.1 的对齐算法，不自己数段落。

1. 渲染完成后收集 `section.docx > article` 下的 `P`、`H1` 到 `H6`、`TABLE`。
2. 把 `blocks` 与收集到的元素做去空白加小写后的前缀匹配，前向 6 个块内查找。对上的元素写 `data-at`。
3. `[data-at="p:N"]` 就是目标。`t:N/rRcC` 找到表后取 `rows[row-1].cells[col-1]`。
4. 滚动自己算容器的 `scrollTop`。范围 `p:N-M` 给范围内每个元素加高亮类。

**quote 高亮。** 在目标块内用 `findTextRange`（6.1.7）。没命中就给整块加高亮类。

**版本核对。** ZCode 用 docx-preview 0.4.0。先看我方 `vendor/docx-preview/docx-preview.min.js` 的版本。不一致时建议升到 0.4.0，并对现有的 docx 预览做一次回归。选择器 `section.docx > article` 以我方这个版本实际渲染出的结构为准。

**解压上限。** JSZip 读完后把各条目的未压缩大小加总，超过 512MiB 就拒绝（对照 `OR/src/adapters/parse/ooxml.ts:91-111`）。

#### 6.1.4 pdf

**不重写。** 把 `web/js/office-viewer.js:179-509` 的 PDF Pro 逻辑原样迁进 `docview/pdf.js`，只做两类改动：

- 状态从 `conn` 对象迁到实例上。原来挂在 `conn._pdfDoc`、`conn._pdfCurrent`、`conn._pdfPageEls` 这些字段上的，改成实例字段。
- 补上定位和高亮：
  - 每页的容器加 `data-at="page:N"`。
  - `goTo` 用容器的 `scrollTop`。
  - `quote`：等目标页的文字层就绪后 `findTextRange(textLayer, quote)`。缩放会重建文字层，要在新层上重新查找（4.2.2）。

#### 6.3.2 识别哪些形态

ZCode 的规则见 4.2.10。有一条不能照抄：**它不认裸文本里的反斜杠路径**，而 Windows 上 AI 输出的几乎全是 `D:\docs\报告.docx` 这种。

| 形态 | 识别 | 说明 |
|---|---|---|
| Markdown 链接 `[文字](路径)` | 是 | 路径可以带 `#锚点`，点了直达那个位置 |
| 行内代码里的路径 | 是 | 支持反斜杠，支持空格 |
| 裸路径，正斜杠，含目录分隔符或以 `./` 开头 | 是 | |
| 裸路径，反斜杠，盘符开头 | 是 | ZCode 不认，我方必须认 |
| UNC 路径 `\\服务器\共享\…` | 仅在行内代码或引号里 | 裸文本里两个反斜杠会被 Markdown 当转义 |
| 带空格的路径 | 仅在行内代码或引号里 | |
| 裸文件名，不带目录 | 否 | 误报太多 |
| 代码块里的路径 | 否 | 不改写代码块 |
| 已有的 `<a href>` | 不动 | 现有逻辑处理 http 和其它协议 |

**后缀的处理：**

- 行号后缀 `:12`、`:12:5` 剥掉。
- 锚点后缀 `#p:12`、`#slide:3` 保留，作为定位参数。ZCode 不认这种后缀，我方是增强：AI 可以在回答里写 `[看这一段](docs/plan.docx#p:12)`，用户一点就到位。

**扩展名判断**要先剥掉 `#` 后缀再比。ZCode 是拿整串去比，所以带锚点的链接不生成卡片。

**可点的扩展名**：`.pdf`、`.docx`、`.xlsx`、`.pptx`，加图片的六种（A10）。大小写不敏感。

2. 遍历文本节点，跳过 `<a>`、`<pre>`、`<code>` 里的。用正则找裸路径，命中就切开，包成 `<a class="hg-doclink" data-doc-open="…">`。
3. 遍历 `<code>`。整个文本就是一个路径的，同样包起来。

#### 6.4.3 等待前端回传

后端没法直接调壳或页面，只能经 SSE 广播再等回传。参照 AI 浏览器的做法（`src/ai_browser.py:83-90` 的 `_ui`，等待上限 `:62` 一带）。

```python
_pending = {}            # req_id -> {"ev": threading.Event, "res": None}
_lock = threading.Lock()

def call_frontend(action, payload, timeout):
    req_id = 新建的唯一标识
    登记 _pending[req_id]
    _broadcast_to_ai({"kind": "ui_action", "action": action, "req_id": req_id, **payload})
    等待，最多 timeout 秒
    取结果并从 _pending 删除
```

| 动作 | 等待上限 | 超时后的文案 |
|---|---|---|
| `doc_open` | 30 秒（对齐 ZCode） | 「文档面板没有响应。请确认 AI 会话页处于打开状态」 |
| `doc_show` | 15 秒 | 同上 |

- 超时和成功都要把 `_pending` 里的条目清掉，不能泄漏。
- 前端回传时 `req_id` 对不上（已超时被清理）就返回 404，前端忽略。
- Flask 是多线程的，字典的读写要加锁。

#### 6.4.4 索引缓存

前端解析完会把大纲和分页文本回传。后端缓存在内存里：

```python
_index = {}      # 规范化路径 -> {revision, info, units, ts}
```

- 最多保留 16 个文档，最近使用的留下。
- 按 revision（大小加修改时间）判断是否还有效。
- 每次 `search` 和 `read` 之前先取一次文件的 revision。变了就当缓存失效，先走一遍打开流程让前端重新解析。

### 6.6 前端回传的数据

`POST /api/doc/report_open` 的内容：

```json
{
  "req_id": "…", "ok": true,
  "document": {
    "path": "D:\\docs\\报告.docx", "kind": "docx", "title": "报告.docx",
    "bytes": 36864, "revision": "36864:1732500000000",
    "outline": [{"at": "p:1", "label": "季度报告", "level": 1}],
    "units":   [{"at": "p:1", "text": "## 季度报告"}, {"at": "p:2", "text": "正文…"}]
  }
}
```

失败时是 `{"req_id": "…", "ok": false, "code": "…", "err": "中文说明"}`。

| 字段 | 说明 |
|---|---|
| `path` | 规范化后的绝对路径 |
| `revision` | `大小:修改时间毫秒` |
| `outline` | 条目格式见 4.2.6。每类文档最多 200 条 |
| `units` | 分页文本的单元。`text` 里是不带前缀的块文本。前缀由后端输出时按 4.2.7 的格式拼。xlsx 的单元另带 `sheet` 和行范围 |

其它两个回传：

- `report_show`：`{ req_id, ok, located: [{ at, found }], path }`。
- `report_view`：`{ path, kind, at, selection: { text } }`。`at` 截到 300 字符，选区文本截到 2000。

**上报时机**：解析完成就报，不等全部渲染完。pptx 和 docx 的文本来自解析阶段，不依赖渲染。xlsx 的单元格值要等引擎解析完工作表。

**截断**：所有截断用 `web/js/docview/text.js` 里 UTF-16 安全的 `cut`。代理对被切开后，整个 JSON 发到后端再转手给模型时会被拒（4.2.12 第 14 条）。

#### 6.7.3 隐藏窗口


**加载**：用 `win.loadFile(input)`，不要手工拼 `file://` 地址。等 `did-finish-load`。脚本里的 `networkidle` 用「加载完成后再静默 500ms」近似。

**等字体**：`webContents.executeJavaScript('document.fonts.ready.then(() => true)')`，上限 5 秒。

**执行函数**：脚本传来的函数会转成源码字符串。壳侧这样执行：

```js
const value = await wc.executeJavaScript(`(${fnSrc})(${JSON.stringify(arg === undefined ? null : arg)})`);
```

返回值必须能转成 JSON，上限 1MiB。单次执行上限 10 秒。

**等待条件**：`waitForFunction` 在壳内轮询，间隔 200ms，直到函数返回真或超时。不在这一次和后端之间反复往返。

**导出**：`webContents.printToPDF(opts)` 得到 `Buffer`。先写到 `output + '.tmp'`，再改名，保证不会留下半截的 PDF。

**关窗**：`win.destroy()`。后端在 120 秒没有新调用后主动关。

**串行**：后端用一把锁，同一时刻只有一个网页转 PDF 会话。

#### 6.7.4 选项怎么对应

脚本里的 `page.pdf(opts)` 用到的选项，和 Electron 45.4.1 的 `printToPDF` 一一对应。Electron 这边的选项名是从它自带的类型声明里读的（`electron/node_modules/electron/electron.d.ts` 的 `PrintToPDFOptions`）。

## 8. 接口汇总

### 8.1 HTTP

| 路由 | 请求体 | 响应 |
|---|---|---|
| `POST /api/doc/open` | `{ path, at? }` | `{ ok, text, document }` 或 `{ ok: false, code, err }` |
| `POST /api/doc/show` | `{ targets: [{ anchor, quote? }], note? }` | `{ ok, text }` |
| `POST /api/doc/search` | `{ path, query, limit? }` | `{ ok, text, hits }` |
| `POST /api/doc/read` | `{ anchor, cursor? }` | `{ ok, text, next }` |
| `GET /api/doc/view` | — | `{ ok, text, view }` |
| `POST /api/doc/report_open` | 6.6 | `{ ok }` |
| `POST /api/doc/report_show` | 6.6 | `{ ok }` |
| `POST /api/doc/report_view` | 6.6 | `{ ok }` |
| `GET /api/doc/stat` | `?path=` | `{ ok, size, mtime }` |
| `POST /api/doc/page/open` | `{ input, viewport? }`，带令牌 | `{ ok, session_id }` |
| `POST /api/doc/page/call` | `{ session_id, method, args }`，带令牌 | `{ ok, value }` |
| `POST /api/doc/page/close` | `{ session_id }`，带令牌 | `{ ok }` |
| `POST /api/doc/page/report` | `{ req_id, ok, value?, err? }` | `{ ok }` |

`text` 字段是给 AI 看的成品文本，MCP 工具原样返回。

### 8.2 SSE 的 `ui_action`

在 `web/js/sense.js:14-47` 的分发里加三个分支。

| action | 带的字段 | 前端做什么 |
|---|---|---|
| `doc_open` | `req_id, path, at` | `DocView.agentOpen(req_id, path, at)` |
| `doc_show` | `req_id, path, targets, note, seq` | `DocView.agentShow(...)` |
| `html2pdf` | `req_id, session_id, method, args` | 调 `fcShell.htmlToPdfCall`，结果回传 |

`seq` 用来去重。同一条连接断开重连后，同一个 `seq` 不会重复触发定位（4.2.12 第 15 条）。

### 8.3 IPC

| 通道 | 入参 | 返回 |
|---|---|---|
| `fc:html2pdf-init` | `{ input, viewport? }` | `{ ok }` 或 `{ ok: false, err }` |
| `fc:html2pdf-call` | `{ method, args }` | `{ ok, value }` 或 `{ ok: false, err }` |
| `fc:html2pdf-close` | 无 | `{ ok }` |

`method` 取 `goto`、`evaluate`、`pdf`、`addScriptTag`、`addStyleTag`、`waitForFunction`、`setViewportSize`。

### 9.2 三端契约

没有编译器帮忙，跨进程的名字只能靠测试钉住。照 `tests/test_ai_browser.py` 文件头第 7 条的做法，把 8.2、8.3、8.6 里的名字在各端的代码里各搜一遍：

### 9.3 两份锚点实现共用一组用例

锚点的解析有 Python 版（`src/doc_store.py`）和 JS 版（`web/js/docview/anchor.js`）。用例放在一个 JSON 文件里，两边都读它：

```
tests/fixtures/doc_anchor_cases.json
[ { "kind": "docx", "input": "p:3-9",  "ok": true, "at": "p:3-9" },
  { "kind": "xlsx", "input": "'Q3 data'!A1", "ok": true, "at": "'Q3 data'!A1" },
  { "kind": "pdf",  "input": "page:0", "ok": false },
  … ]
```

每个格式至少覆盖：单个位置、范围、形状或单元格这类带子定位的、带引号的表名、从 0 开始的序号、超上界、空串、超过 300 字符。

### 9.4 测试的质量

这个项目在对抗审计里吃过两种亏，写测试时要避开：

- **恒真断言。** 断言写成 `assert x is not None or True` 之类的，或者断言一个永远成立的条件。
- **名字说测了，其实没测。** 用例名写着「切会话后恢复」，里面却只检查了函数能调用。

每条断言都要能在代码写错时失败。写完问自己一句：把实现里的某一行改坏，这条断言会不会红。

### 9.5 写盘的测试必须先证隔离

本任务里有两处测试会写盘：

| 写哪里 | 怎么隔离 | 怎么证 |
|---|---|---|
| 技能同步 | 环境变量 `FC_SKILLS_TARGET` 指到临时目录 | 被测函数**返回或日志里回报**它实际写入的路径，断言这个路径在临时目录下。不能只看测试脚本里设的变量 |
| 网页转 PDF 的输出 | 输出到临时目录 | 同上 |

另外两条：

- 运行前后对真实的 `~/.claude/skills` 做一次指纹，出现差异必须查清来源。
- 测试文件如果自己不导入 `app_state` 却用子进程跑被测代码，子进程认不出测试身份，会碰真实的目录。这种文件要在顶部显式设 `os.environ["FC_TEST_CHILD"] = "1"`，参照 `tests/test_harness_version.py`。

## 附录 B：ZCode 的工具定义原文

实施时把描述改写成中文，语义保持一致。`${…}` 是 ZCode 按文档类型替换的占位符。

**`open_document`**（`OR/src/adapters/server.ts:181-196`）

> Open a ${EXTENSIONS_OR} file from the workspace in the ${TITLE} viewer panel, which the user sees. Optionally jump to a location. Returns the document's outline and how to address locations in it. Use this when the user wants to view, review or discuss ${FILE_NOUN}.

参数：`path`，「Workspace-relative path of the file.」；`at`，「Optional location to show」。

**`read_document`**（`:203-217`）

> Read a document you are discussing with the user in the ${TITLE} panel, or one location in it, as text: ${READ_FORMS}. Use it to answer about the open document or anchors the user referenced. Open the document with open_document first. Each block is prefixed with its location, an anchor the panel understands: cite it or pass it to show_in_viewer, with an exact `quote` copied from the text to highlight a phrase. Long results are paged: call again with the returned cursor. To extract or process ${FILES_NOUN} outside the panel, use the ${SKILL_NAMES} skill instead.

**`search_document`**（`:232-241`）

> Find text (case-insensitive) in a document you are discussing with the user in the ${TITLE} panel. Open the document with open_document first. Returns matching locations as anchors with a snippet each; pass them to read_document or show_in_viewer. To search or extract ${FILES_NOUN} outside the panel, use the ${SKILL_NAMES} skill instead.

**`show_in_viewer`**（`:261-277`）

> Point the user at specific places in a document: the ${TITLE} panel opens the document, scrolls to the first target and highlights all targets. Use it whenever your answer refers to a particular ${TARGET_NOUNS}. All anchors must be in the same document. `quote` highlights that exact text inside the location (best for ${QUOTE_BEST_FOR}).

`note` 的说明是：「Optional short caption shown in the dedicated Agent panel next to the highlight; manual document windows are not retargeted.」

**`get_view`**（`:288-298`）

> See what the user is looking at in the ${TITLE} panel: the open document, the visible location and the user's current selection with its text. Call this when the user says "this", "here" or "the selected …" about a document.

**锚点写错时的提示**（`OR/src/domain/anchor.ts:27-32`）

```
docx: "Use p:N, p:N-M, t:N or t:N/rRcC."
pptx: "Use slide:N, slide:N-M or slide:N/shape:ID."
pdf:  "Use page:N or page:N-M."
xlsx: "Use Sheet, Sheet!A1 or Sheet!A1:C9 (quote names with spaces: 'My sheet'!A1)."
```

建议的中文：

| 类型 | 提示 |
|---|---|
| docx | 段落用 p:N 或 p:N-M，表格用 t:N，表格里的单元格用 t:N/r行c列 |
| pptx | 幻灯片用 slide:N 或 slide:N-M，幻灯片上的形状用 slide:N/shape:ID |
| pdf | 页用 page:N 或 page:N-M |
| xlsx | 用表名、表名!A1 或 表名!A1:C9。表名带空格时要加单引号：'My sheet'!A1 |

**整条锚点不合法时**（`anchor.ts:170-179`）：

> "<原文>" is not a document anchor. Use <path>.docx|.xlsx|.pptx|.pdf optionally followed by #<location>.
